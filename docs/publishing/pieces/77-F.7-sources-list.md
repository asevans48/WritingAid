## Phase context

Phase F makes the app work for stories that are not novels, **keeping every
story feature**: plot, characters, world, critique, the Improve window, Read
Aloud, the Studio. Agreed with the writer on 26 November 2026 (README
decision 18):

- **Kinds.** A project has a kind, chosen when it is created and changeable
  later: **Novel** (novels and novellas, as today, and the default for every
  existing project), **Video series**, **Podcast**, **Editorial series**,
  **Journalism**.
- **Same shape for every kind.** A project still holds a main manuscript,
  novellas and chapters. A kind changes the words on screen (set by the
  kind, editable per project), which checks and goals apply, and what
  publishing prepares. A chapter is one video, one episode or one part.
- **Nothing a novelist has changes.** A Novel project looks and behaves
  exactly as it does before this phase (rule 11). Every test of today's
  behaviour keeps passing unchanged.
- **Phase F comes after the final sweep (9.1).** Sending anything to a site
  (YouTube and others) stays a later integration (decision 7); this phase
  prepares the material.

## The piece

- **Why:** a true story, an essay or a report rests on where its facts
  came from.
- **The writer gets**, for Journalism and Editorial series (and offered
  for a true-story Video series or Podcast):
  - A **sources list** for the project: people, documents, links,
    recordings; for each, who or what it is, the date, how to reach it,
    whether it is on the record, and notes.
  - **Pointing a quote or a claim at its source:** select the text,
    right-click, choose the source. The link is shown quietly and can be
    opened.
  - A source's page lists every place it is used.
- **Where it lives:** check the attributions screen first. If it already
  holds something like this, extend it rather than add a screen
  (rule 13); say which in *Outcome*.
- **Where it is stored:** beside the project (a file of its own, as
  `<project>.submission.json` is), so a Novel project's file is
  unchanged. Links survive editing around them; if the text is deleted
  the link goes quietly, and the source stays.
- Private details of sources stay on the writer's machine: they are
  never put in a prompt to a cloud model unless the writer says so.

## Tests

- Add, edit and remove a source; link and unlink text; the link follows
  edits; a deleted source asks first and leaves the text alone.
- Save and reopen; export without the private fields.
- A Novel project has no sources file and is unchanged.

## What has changed since this brief was written

_Added 26 November 2026 from [F.0's design](70-F.0-project-kinds-design.md) (section "Changes the other phase F briefs need"; read the design first)._

- a link from text to a source can be an existing annotation
  (`annotation_type="attribution"`, `referenced_type="source"`), which the
  Attributions screen already lists. But annotations are anchored by
  `line_number`, which does not follow edits. Decide the anchor (for
  example the quoted text, as proofreading keeps by paragraph text).
  Sources go in `<project>.sources.json`.

  A new kind's own figures are recorded and put to the writer.
