## The piece

- **This session: the two remaining new reports** (homonyms, sensory detail)
  **and the two extensions** (sentence structure, diction). Follow the pattern
  P.2a established; read its *Outcome* first.
- **Goal:** every ProWritingAid writing report has an equivalent here, except
  plagiarism.
- **Add:**
  - **Transitions:** share of sentences that use a transition, and passages with
    none.
  - **Pronouns:** overused pronouns and runs of sentences starting with one.
  - **Alliteration:** runs of words with the same opening sound.
  - **Homonyms:** words easily confused with one that sounds alike, for the
    writer to confirm.
  - **Acronyms:** acronyms used inconsistently or never spelled out.
  - **Sensory detail:** which senses a passage uses and the balance between
    them. It pairs with the overly descriptive check, since both are about
    showing versus telling.
- **Extend:**
  - **Sentence structure:** variety of structures, beyond repeated starts.
  - **Diction:** vague and abstract words, beyond wordy phrases.
- **Confirmed in 0.1:** repeated phrases exist (`OveruseDetector.analyze_phrases`,
  shown in the editor as "Repeated phrase"). A combined view exists only
  partly: the editor's highlights show spelling, grammar, overuse and style
  together, but no single report lists them all. The Style panel lists the
  eleven style checks only. Transitions and sensory detail are named in the
  Critique's model prompts, but nothing counts them.
- **Build:** each as a new kind in `src/utils/style_checks.py`, so it appears in
  the highlighter, the issues list and the readiness report without further
  work. New kinds are off in existing projects until the writer turns them on
  (rule 11).
- **Declutter:** no new screen. The kinds appear in the existing list of checks.
- **Tests:** each new check is added to the benchmark and must meet the Q.2
  target before it is on by default for new projects.
- **Done when:** the report-by-report table in [background.md](../background.md) shows no
  "missing" or "partly".

## What has changed since this brief was written

_Added 24 November 2026, after phase 3, D.3 and 2.5 were built. Read the Outcome of each piece named here._

- **The issues list is now the next-fix queue** in the Companion (3.2, D.3).
  A new style kind reaches the queue only if it is added to
  `STYLE_ONLY_KINDS` in `src/ai/fix_queue.py` (kinds no readiness check
  reports) or reported by a readiness check. Decide which for each new kind.
- **The switches** for each kind are in the Write menu's Style checks submenu
  (`src/ui/style_checks_menu.py`) as well as the Style tab. Check each new
  kind appears in both, off in existing projects.
- **Rule 13:** the Write menu is already at 40 items against a baseline of 29,
  because of that submenu. New kinds add more. Say in *Outcome* what the
  count is, and see [D.6](48b-D.6-retire-the-trial-screens.md).
- **"Fix all N like this"** (3.4) now works for any flag with a short fix.
  A new kind with suggestions gets it without further work; check it makes
  sense for the kind, and leave suggestions empty where it does not.
- **Added 24 November 2026 by P.2a.** The pattern for a new kind is in
  [P.2a's Outcome](31-P.2a-missing-reports-transitions-pronouns-alliteratio.md#outcome):
  detectors live in `src/utils/style_reports.py` (called from
  `style_checks._analyze`), kept out of `DEFAULT_KINDS` so they start off;
  `analyze_paragraph` now takes an optional `document` (the whole chapter)
  for checks that look beyond the paragraph. Benchmark passages for new
  kinds carry a `"scores"` list so the earlier checks' numbers do not move.
  Write's menu count is now 52 (each new kind adds one). The Style tab shows
  a check's count only while it is on.
- **Added 24 November 2026 by D.6.** The Style tab is retired
  (`src/ui/style_panel.py` is gone). A new kind needs only its entry in
  `KINDS`: the Style checks submenu lists it with its count, and the
  Companion card's "every style issue" list (✓ Checks ▾ → Style issues
  panel…, `Queue.show_style_issues`) shows it whatever the stage. The
  harness counts the Style checks submenu as **one** entry (decision 11),
  so a new kind no longer raises Write's menu count; the every-item count
  (53 now) still rises by one.
