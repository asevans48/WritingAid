## The piece

- **The writer gets:** **Listen to this chapter**, with the sentence being read
  highlighted, pause and resume, and one key that marks the current sentence.
- **Read first:** `src/services/tts_service.py`, `src/ui/export_audio_dialog.py`.
- **Tiers:** uses whichever speech engine is already set up. With none
  available, the button explains that and offers nothing else.
- **Done when:** a chapter plays and marks are captured against the right
  sentences.

## Build notes

_Added 24 November 2026 so a fresh session can finish this piece without searching. Names were checked against the code on that date; if one has moved, find it with a search and say so in Outcome._

- **Read first:** `TTSService` in `src/services/tts_service.py` (`speak`,
  `pause`, `resume`, `stop`, `is_speaking`); in
  `src/ui/manuscript_editor.py`: `_tts_speak_chapter`, `_tts_stop`,
  `_on_tts_progress`, `_on_tts_started`, `_on_tts_stopped` and the
  "🗣 Read Aloud ▾" menu.
- **Where:** an item in the existing Read Aloud ▾ menu, "Listen and mark".
  No new button.
- **Find out first** whether the speech engine reports where it is. If it
  only reports start and stop, read one sentence at a time (`speak` per
  sentence) so the app knows which one is playing; say which in *Outcome*.
- **The highlight is not an edit.** Use an extra selection on the editor, so
  nothing reaches the undo stack or the saved text.
- **Marks:** stored per chapter in `companion_state` under a new key, each
  with the sentence's text and its place. A mark whose sentence has changed
  is kept and shown as "the text has changed".
- **Tests:** with a fake engine, the highlighted sentence follows playback,
  the key marks the current sentence, pause and resume keep the place, and
  the chapter's text and undo stack are unchanged.
