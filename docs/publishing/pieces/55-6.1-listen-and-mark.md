## The piece

  highlighted, pause and resume, and one key that marks the current sentence.

## Outcome

**Built 25 November 2026. Not yet tried by the writer with a real voice:
every test uses a fake speaker.**

**What the writer does:** Write toolbar, **🗣 Read Aloud ▾ → 👂 Listen and
mark**. With text highlighted, only the highlighted text is read and marked
(cut to the highlight where it begins or ends mid-sentence); otherwise the
whole chapter, from the top. *Changed 25 November at the writer's request:
it used to start at the cursor's sentence and ignore a highlight.* While
listening, the highlight is set aside so the sentence being read shows,
and it comes back when listening ends. The sentence being read is highlighted in
yellow; the button shows the place, e.g. "⏸ 4/9 · 1 marked".

- **Space** pauses and resumes (so does clicking the Read Aloud button).
- **M** marks the sentence being read; **M** again on it unmarks it. Marked
  sentences stay tinted violet and underlined while listening.
- **Esc** stops (so does ⏹ Stop reading). The end of the chapter stops too.
- While listening these three keys do not type; every other key types as
  usual, and the sentences follow the edit (each is held by a
  `QTextCursor`). A sentence deleted while listening is skipped.
- **🗣 Read Aloud ▾ → Marks in this chapter (n)** lists the marks (shown
  only when there are some); choosing one selects its sentence. A mark
  whose sentence has changed is listed with "(the text has changed)" and
  kept.
- **No speech voice:** the entry says so in the status bar and does
  nothing else.

**Where it is (rule 13):** two entries inside the existing Read Aloud ▾
menu, which decision 11 counts as one grouped entry. No new button. Write
counts are unchanged: buttons 19 (19), menu items 29 (29), right-click 9 / 13
(9 / 13). Every-item count 58 (57 before; the marks submenu is hidden while
empty).

**The engine reports only start and stop**, never where it is. So each
sentence is spoken on its own (`TTSService.speak` per sentence), and a
100 ms timer moves on when `is_speaking` turns false. Pause uses the
engine's pause (macOS voices); an engine that cannot pause is stopped and
says the sentence again on resume. With a neural engine set in Read Aloud
(Kokoro, Chatterbox, VibeVoice) each sentence is generated separately, so
there may be a gap between sentences. Read Aloud's optional "enhance text
for speech" model step is not used (it would be one model call per
sentence). While listening, the editor's speech callbacks are set aside so
the button is not reset after every sentence, and restored afterwards.

**The highlight is not an edit:** extra selections on the editor, tagged so
other extra selections (e.g. the main window's flash) are left alone. The
text, undo stack and modified flag are unchanged (tested).

**Marks (for 6.2):** `src/data/listen_marks.py`, in the project's
companion file (`companion_state`, R.7), per chapter under
`chapters[<chapter id>]["heard_marks"]`, a list in the order made:

    {"id": "3f9c0a1b2c4d", "text": "<the sentence as heard>",
     "start": 25, "end": 46, "paragraph": 0,
     "made": "2026-11-25T10:31:05", "source": "listen"}

`start`/`end` are offsets in the editor's plain text at the time;
`paragraph` is the 0-based block. Each mark is saved the moment it is made.
Calls: `marks(project, chapter_id)`, `add(...)`, `remove(project,
chapter_id, mark_id)` (6.2: call it when a mark is fixed or dismissed),
`resolve(mark, chapter_text)` → `(start, end, SAME | MOVED | CHANGED)`, and
`CHANGED_LABEL` = "the text has changed". Every other key in the file is
left as it was (tested). Missing or damaged entries read as no marks.

**Files:**

- new `src/ui/listen_mark.py`: `Speaker` (the interface), `SystemSpeaker`
  (Read Aloud's `TTSService`), `ListenSession` (`start`, `pause`,

- new `tests/test_listen_mark.py` (14 tests).
- `tests/test_editor_toolbar.py`: one assertion lists the Read Aloud menu
