## The piece

- **Why:** `ProWritingAnalyzer` and `style_checks.py` both measure passive
  voice, adverbs, clichés, echoes and sticky sentences. Two versions can
  disagree, and each fix has to be made twice.
- **Do:** keep one implementation of each check (the better one by the Q.2
  table) and have the other call it.
- **Needs:** Q.2, so the numbers before and after can be compared.
- **Done when:** each check exists once and the Q.2 table is unchanged or
  better.

- **Data safety:** the names of the style checks are stored in style sheets,
  ignored-issue lists and the highlight settings. Merging the two analysers
  keeps every existing name with the same meaning. No stored name is
  renamed or reused.

## Outcome

**Status:** done. Each of the five shared checks now exists once.

**The choice: `style_checks` for all five.** Q.2's side-by-side table put
`ProWritingAnalyzer` ahead on passive voice. Looking closer, that was an
artefact. It marks whole sentences, and its rule only knows "-ed" words plus
ten irregular participles, so it never sees "was thrown", "was sunk", "was
born" or "was built" (checked directly). It scored well on the deliberate
passives only because it could not see them. `style_checks` finds those
passives and wins or ties on the other four, so it is the one
implementation.

**Changed:** `src/utils/writing_stats.py` (`ProWritingAnalyzer`, the
Critique's numbers):

- One `style_checks.analyze_document` pass per analysis, with the editor's
  set of kinds (`EDITOR_STYLE_KINDS`, so sticky sentences skip long ones as
  in the editor), feeds passive voice, adverbs, clichés, sticky sentences
  and echoes. `_analyze_passive_voice`, `_analyze_adverbs`,
  `_detect_cliches`, `_analyze_sticky_sentences` and `_analyze_echoes`
  keep their names and fill the same fields, with the same types and
  meanings: lists of sentences or words, (word, earlier index, later index)
  echo pairs, counts and percentages. The glue index uses the same glue
  words as the sticky check.
- Its own word lists are gone. `GLUE_WORDS` and `CLICHES` stay as
  references to `style_checks.GLUE` and `CLICHES`, for existing readers;
  `COMMON_ADVERBS`, `PASSIVE_HELPERS` and its passive pattern are removed.
- `style_checks.py` itself is not changed.

**Q.2 table: unchanged.** The editor's checks score the same on every row
(compared programmatically before and after). The side-by-side section now
says the two columns come from one check.

**What the writer will see: the Critique's style numbers change.** On the
clean prose, per 1,000 words, before and after:

| Measure | Before | After |
|---|---|---|
| Echoes | 34.7 | 10.9 |
| Adverbs | 20.0 | 13.5 |
| Sticky sentences | 26.4 | 18.8 |
| Passive voice | 3.1 | 2.4 |

Irregular passives now count. The Critique and the Style panel now agree:
the disagreement `screens.md` recorded in 0.2 is gone.

**Data safety:** no stored name changed. The eleven style-check kinds,
which style sheets, ignore lists and highlight settings store, are the
same, and a test checks them. Critique history written before the change
still loads. Its counts are simply measured more consistently from now on,
so the first run after this piece may show style counts moving although
the text did not.

**Tests:** `tests/test_one_style_analyser.py`, 5 tests:

- the Critique's counts equal the editor's flags;
- the fields keep their shape;
- there is no second copy of the word lists;
- the stored names are unchanged;
- empty text gives empty statistics.

Full suite: 999 passed, plus the same 4 `test_overuse_context.py` failures
that were already failing.
