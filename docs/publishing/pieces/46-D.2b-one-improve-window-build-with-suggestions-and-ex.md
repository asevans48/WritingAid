## The piece

- **This session: build the shared window to the design agreed in D.2a,** and
  move Suggestions and Expand into it. Rephrase is left as it is until D.2c.
  The old windows keep working (trial, then retire).
- **The writer gets:** one window for help with a passage, replacing three.
  Tabs along the top: **Suggestions**, **Rephrase**, **Expand**, **Critique**.
  The lower half is shared: the options, an editable preview, the changes
  from the original, the rating buttons, and "Talk it through".
- **Build:** a shared window in a new module. Each existing tool supplies its
  options to it. The existing windows' classes remain as thin wrappers, so
  every place that opens them keeps working.
- **Read first:** `src/ui/passage_critique_dialog.py`, `src/ui/rephrase_dialog.py`,
  `ExpandStatementDialog` in `src/ui/overdescription_panel.py`,
  `src/ui/rewrite_chat_panel.py`.
- **Each tool keeps its own model,** as configured today (rule 2).
- **Risk:** Rephrase is the largest of the three and has its own tests. If the
  merge threatens its behaviour, stop at Suggestions plus Expand and report.
- **Done when:** one window opens from every place the three did, existing tests
  pass, and it fits 1024 × 600 with scrolling.

- **Agreed in 0.2:** the merge goes ahead, with no feature cut. Build to the
  D.2a design and tick its capability checklist for Suggestions and Expand.

- **Data safety:** accepted text goes into the chapter through the same call the
  old windows use, with the same check that the passage is still where it
  was. Ratings are logged to the same place with the same values.

## Outcome

**25 November 2026: built, for review. Nothing committed.**

**What the writer gets.** Right-click ▸ ✨ Improve this ▸ 💡 Suggestions… or
🔍 Overly descriptive?… (and every other place that opened those two
windows) now opens one **Improve** window, titled "Improve — <first words>",
over the window you are in. Tabs: **💡 Suggestions · 📝 Critique · 🔍 Expand**
(Rephrase's place, third, is kept for D.2c). Under the tabs everything is
shared: one versions list, **Your version** (editable, ✏ edited, ↺ Reset;
edits stay with their version, no question), Why and ⚠ notes, the changes
from your text, the rating row with 🚫 Avoid a phrase…, Talk it through,
and **Close / ✓ Accept**, which never scroll away. The Critique is the same
model call as Suggestions, now its own tab. Expand is the old panel; its
✓ Accept is called **Apply to passage** here and builds "Your text,
expanded" in the versions list. Keys: Ctrl+1 Suggestions, Ctrl+2 Critique,
Ctrl+4 Expand (Ctrl+3 is Rephrase's, from D.2c), Ctrl+Return accepts, Esc
closes; Return in Focus regenerates and in a direction line asks for more
ideas, and never accepts by accident.

**The old windows, one tick away.** Settings ▸ Features ▸ **Improve
window**: "Open Suggestions and Overly descriptive? in one Improve
window". Ticked by default (decision 16), stored as `improve/merged` beside
the window positions; missing or unreadable means ticked. Unticked, the
old `PassageCritiqueDialog` and `ExpandStatementDialog` open exactly as
before. Rephrase is unchanged (D.2c).

**Callers (D.2a §5).** All go through `ChapterEditor.suggest_for_span` and
`ChapterEditor.expand_statement`, which now call `improve.open(self, tab,
…)` when the switch is on (three call lines each). Their signatures and
return values are unchanged, so a True from any tab still clears the
Companion note, 👂 mark or fix. Rows 3 and 4 (right-click), 7 (next-fix
card's More options), 8 (Suggest fix on a note or 👂 mark), 9 (Companion's
Expand…), 10 (Critique report links) and 11 (scorecard's Ways to expand
it…) land on Suggestions (Focus filled) or Expand. Rows 1, 2, 5, 6 and 12
(Rephrase) are D.2c's.

**Data safety.** Accept hands back `replacement`, `span` and `tool`;
`improve.apply` puts the text in through `_replace_span(…, "Suggestions")`
or `_replace_span(…, "Overly descriptive")`, with its check that the
chapter has not changed. Ratings use the old calls with the old values
(tested row by row against the old windows): Suggestions and Critique
versions `log_rated_rewrite` style "suggestion"; applied expansions
`log_accepted` (style "expansion"); "Your text, expanded" counts as a
Suggestions version once Suggestions has run (as in the old window), and
before that can be rated, saved with style "expansion" (decision 16), with
no extra row on Accept (as the old Expand window). Nothing new is stored in
the project.

**No wasted calls.** A tab runs the first time it is shown. A Suggestions
run also fills Expand, unless Expand already ran (`SuggestionWorker` has a
new optional `review=True`; the Improve window passes False then). With no
model, Suggestions' status line says so and links to 🔍 Expand ("still
shows the word scan, clues, not proof"), and the window moves to Expand
when the scan found something, as the old window did.

**Counts.** Right-click 7 without a selection and 11 with one (was 9 /
13): ✨ Improve this ▸ now counts as one group (decision 16;
`GROUPED_MENUS` in the harness; `screens_baseline.json` lowered to match;
screens.md updated). Every other count is at its baseline. The window is
in the harness as `improve`, `improve_critique` and `improve_expand`:
buttons 10 / 9 / 12, 1 section, 3 tabs; counted, not yet in the baseline
(section 3 asks). The three old windows had 24 buttons between them.

**Fits.** `fit_to_screen(1100, 780)`, then `remember_geometry(…,
"improve_window")`. Everything between the passage and the buttons
scrolls. Pictures looked at, all with no problem reported: 1024 × 600,
1440 × 900, 2560 × 1440 and 1440 × 900 at 150% for each tab, plus a
1500-wide window for the Talk it through column. Heights follow the font,
no fixed pixel heights on text. At 1024 × 600 the versions start about
half-way down and the rest scrolls; at 1440 × 900 nothing on the
Suggestions tab scrolls. Talk it through is a closed section (remembered)
while the window is under 1,200 px wide (`ui_kit.size_class`), which
includes its default 1,100; a third column when wider.
