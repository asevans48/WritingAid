### 1. Undo removes a novella only when it is truly empty ✓

**What counts as a novella's content** (`src/data/novella_content.py`,
`holds`; read directly, nothing written). Found out first: worldbuilding,
characters, plot planning, story memory, the style sheet, the dictionary,
the prose profile and the Video Studio are the **project's**, shared by
every manuscript (`Subproject` owns only its manuscript; nothing in them
names a novella), so nothing there can belong to a novella and they are
not looked at. What a novella can hold of its own:

- in the project file: its **chapters** (with their outlines, planning,
  feedback, annotations), its **drafts**, and its name, description, kind
  and its manuscript's title and author, which count only when **changed
  since the move made it** (a snapshot is taken then): the description
  you type in "＋ A new novella…" came with the move, so Undo takes it back
  with the novella;
- in `subprojects/<id>/`: **any file** but its `subproject.json` (its
  chapters' own folders are said as "chapters");
- beside the project, under its id: in the readiness file its part of
  `manuscripts` (publishing route, readiness results and stages, book
  checks, their history) and its part of every other section (editorial
  letter, voice reading, scene markers, digests, ledger, plan matches,
  scene tension, and any section added later, as "saved results"); its
  **submission drafts** (`<project>.submission.json`); its **Improve notes**;
  the **Critique's reports** on it (`critique_history.json`, keys naming its
  id).

Empty containers do not count (Undo moves the chapters' entries back and
can leave `{"chapters": {}}`), so results made on a chapter while it was in
the novella go back with it and the novella still goes. An **unreadable
file counts as content** (never assumed empty) and is left as it is.

It applies to every move that makes a novella (Turn main manuscript into a
novella…, the first novella's "Move into …", Move to ▸ ＋ A new novella…),
named by you or by the move (`manuscript_tree.remember_made`, two call
sites; `_drop_made` asks `novella_content.holds`; `_has_files` kept). The
words after Undo:
- "Put back where it was. “Novella 1” was removed."
- "Put back where it was. “Novella 1” was kept: it has submission drafts."
  (also "it has chapters", "it has drafts and Critique reports", "it has a
  description", "it has a new name", "it has files in its folder" …)

The question before a whole-manuscript move now says "…removes “Novella 1”
(unless something has been added to it or saved for it since)."

### 2. The Improve window's notes are kept ✓

**The file:** `<project>.improve_notes.json` beside the project file
(`~/.creativeos/improve_notes/` for a project not yet saved), its own file
(`src/data/improve_notes.py`). Not inside the readiness file: it holds
whole passages and versions, and the readiness file is rewritten (compact)
on every check and read often, so it is kept small; damage to one never
touches the other. **Format** (the readiness file's layout, so a chapter
move carries it with the same `move_entries`):

    {"format_version": 1, "manuscripts": {"main" | <novella id>: {"chapters":
      {<chapter id>: {"notes": [{"id", "when", "passage", "accepted",
        "critique": {"issues", "dialogue", "order", "works"},
        "versions": [{"text", "source", "why", "rating"}],
        "dismissed": ["c:issues:0", "v:1"]}]}}}}}

One record per Improve window, **appended when it closes** (the existing
call line in `ImproveWindow.done`), written through `safe_store` (a
temporary file swapped in), under a lock; a damaged file is set aside and
you are told, never saved over; a file from a newer version is read-only.
Never sent anywhere. **Cap: the newest 200 records (Improve windows) per
chapter**; the oldest goes when the 201st is added. If the file cannot be
written, the notes are kept in memory for the session, as D.13c did.

**The Feedback tab** reads the file directly (reading writes nothing; no
file means nothing to show, so a project without it opens as before). A
record's items show only while its passage or accepted words are in the
chapter (now also for this session's, as for rated versions). Each Improve
item has a **Dismiss** link beside Go to · Open in Improve: hidden, and
kept in the file in the record's `dismissed` list. It is a link, so no
count rises.

**Moves:** `chapter_move._move_state` carries the chapter's notes to the
new manuscript's part (and records the file's bytes, as for the readiness
file); Undo moves them back, byte for byte when nothing changed since, and
notes added while it was in the novella go back with it.
