## Phase context

**The idea.** Ratings stay in one shared store, so everything rated in any
project keeps teaching the app. Each rating is tagged with the voice of the
writing it was given to. Ratings fall into a small number of voice groups.
When the app writes a rewrite, it learns first from ratings in the same voice
group as the passage, whichever project they came from. Two books in different
voices stop colouring each other; two in a similar voice help each other; and
one book with several narrators gets a group for each.

**My reading of "broad, manageable".** Broad: shared across projects, with a
few large groups, not many small ones. Manageable: the writer can see the
groups, rename them, move a rating, merge two groups, and remove ratings.
Correct this in the review notes if you meant something else.

## The piece

- **Build:** when a rating is saved, also save the voice measures of the
  writing it applies to: sentence length and spread, paragraph length,
  contractions, adverbs, punctuation habits, person and tense, and how
  sentences open. These come from `analyze_writer_voice`, which needs no
  model and takes a few milliseconds.
- **Which text is measured:** the narration around the original passage, not
  the passage alone, since one sentence is too little to measure.
- **Storage:** a new table beside the ratings in the same database, linked by
  the rating's id. The existing table and its rows are not altered.
- **Existing ratings:** given a fingerprint the first time they are needed, from
  their stored original text and context. A rating with too little text is
  marked "unsorted" and still used as it is today.
- **Check first:** the ratings table already has a `voice` column. Record what
  it holds today and leave it as it is.
- **Read first:** `src/ai/writer_voice.py`, `src/data/rephrase_database.py`,
  `log_rated_rewrite` in `src/ai/rewrite_quality.py`.
- **Tests:** a database created before this piece opens and gains fingerprints
  without losing or changing a row; an older version of the app still reads
  the database.
- **Done when:** new and existing ratings have fingerprints.

- **Data safety:** the ratings database holds about 200,000 rows. This piece
  only adds a table. It does not alter, rewrite or delete any existing row or
  column. Before the first change, the database file is copied aside once
  (`rephrase_history.db.before-voice`). Run the stores comparison before and
  after.

## Outcome

_Built 25 November 2026._

**What was built.** Every rated rewrite gets a voice fingerprint: a
fixed-order list of 23 numbers measured on the narration around the rated
passage, stored in a new side table beside the ratings. No model; the
`rephrases` table, its columns and its rows are untouched.

**Files.**
- New `src/ai/voice_fingerprint.py`: the pure measure.
  `fingerprint(text) -> Fingerprint` (`version`, `status` "ok" |
  "unsorted", `vector`, `word_count`, `sentence_count`, `.ok`,
  `.as_dict()`); `vector_of(text)` (list or None);
  `rating_text(before, source, after)` (the text a rating measures: up to
  6,000 characters before, the passage, up to 6,000 after);
  `MEASURES`, `LABELS` (plain words), `VERSION = 1`,
  `MIN_SENTENCES = 5`, `MIN_WORDS = 60` (the same bar as
  `analyze_writer_voice`; below it the rating is "unsorted", no vector, and
  is still used as today).
- New `src/data/voice_fingerprint_store.py`: the table, the copy aside,
  the backfill and the reads. `prepare_on_open`, `ensure_table`,
  `record_new_rating`, `backfill(db, batch=200, should_stop=None)`,
  `missing_count`, `fingerprint_for(db, row_id)` (lazy: computed and stored
  the first time asked), `fingerprinted_ratings(db, include_unsorted=False)`
  (for V.2: `id, project_path, character_name, rating, accepted,
  source_type, status, vector`, joined from `rephrases` so
  `project_path` and `character_name` stay where they always were),
  `start_background_backfill`, `stop_background_backfill`,
  `FINGERPRINT_SOURCE_TYPES = ("rephrase",)`.
- `src/data/rephrase_database.py` (call lines only): `__init__` calls
  `prepare_on_open`; `log` calls `record_new_rating` after the insert has
  committed.
- `main.py`: `_fingerprint_ratings_later()` starts the background backfill
  30 seconds after start-up (a `QTimer`, the work on a daemon thread).
- New `tests/test_voice_fingerprint.py` (14 tests).

**The measures (version 1, vector order).** 0 `sentence_len_mean`,
1 `sentence_len_spread`, 2 `short_sentences_pct` (<8 words),
3 `long_sentences_pct` (>25), 4 `sentences_per_paragraph`,
5 `word_len_mean`, 6 `contractions_per_100_words`,
7 `adverbs_per_100_words`, 8 `em_dashes_per_100_sentences`,
9 `semicolons_…`, 10 `colons_…`, 11 `ellipses_…`, 12 `exclamations_…`,
13 `questions_per_100_sentences`, 14 `first_person_pct` and
15 `second_person_pct` (shares of personal pronouns), 16 `past_tense_pct`
(past markers / past + present), 17–21 how sentences open, % of sentences:
`opens_pronoun_pct`, `opens_article_pct`, `opens_conjunction_pct`,
`opens_ing_pct`, `opens_name_pct`, 22 `dialogue_pct` (share of all words
inside quotation marks). 0–4, 6–13 and 17–21 are
`analyze_writer_voice`'s own figures (narration only); 5, 14–16 and 22 are
computed beside them in the same way. Any change to these or to how
`analyze_writer_voice` computes them must raise `VERSION`; stored
fingerprints of another version count as missing and are recomputed by the
next backfill.

**Speed.** 0.3 ms for a 250-word passage, 1.3 ms for 1,000 words, 7 ms
for 6,000 words (a rating's text is at most about 2,500 words, so about
3 ms).

**Which rows.** Rows with `source_type = 'rephrase'` (the rated rewrites;
419 in the writer's database on 25 November, of which 250 are synthesised
from corpora and 169 carry a project path; 165 have more than 200
characters of context, so many older ones will be "unsorted"). Chat,
critique, plot, character, worldbuilding and the 197,757 catalog corpus
rows are prompts or downloaded text, not ratings of prose, and are not
fingerprinted.

**The `voice` column today.** Empty on 202,845 rows;
`adelphus---born-in-blood` on 901 (a corpus label set by the importer).
Left exactly as it is; V.1 does not read or write it.

**Storage.** Table `voice_fingerprints (rephrase_id INTEGER PRIMARY KEY,
version, status, vector TEXT (JSON list), word_count, sentence_count,
created_at)`. An older app never looks at it; deleting a rating in an older
app leaves a fingerprint that every read ignores (reads join on
`rephrases`).

**Backup and backfill on the real database.** Opening the database never
copies or creates anything when it has rows. 30 seconds after the app
starts, a background thread opens it, and, because the table is not there
yet, copies the whole file once to `rephrase_history.db.before-voice`
(SQLite's backup API in steps, so it is consistent and the app's own writes
are not held up; written as `.before-voice.partial` and renamed only when
complete and its row count matches). The file is about 1.9 GB, so the copy
needs that much free space plus 0.5 GB; with less, nothing is created and
it tries again on the next start. Then it creates the table and
fingerprints the ratings in batches of 200, each batch committed on its
own, so quitting mid-way loses nothing and the next start carries on. With
419 ratings this takes under two seconds after the copy. From then on each
new rating is fingerprinted as it is saved (a few milliseconds). A new,
empty database gets the table at once (nothing to copy). The copy is never
made a second time. The stores comparison sees one new table and no fewer
rows.

**Tests.** The pure measure (order, purity, voices told apart, too little
text, dialogue, speed); a new database fingerprints new ratings and keeps
`project_path`/`character_name`; a database made before V.1 opens
unchanged, gains fingerprints in resumable batches with every row and
column byte-identical, and the copy aside equals the database as it was;
the copy is made once; no table when the copy cannot be made, and saving a
rating still works; a stale partial copy is replaced; an older app's schema
step and reads still work and see the same 16 columns; the background job;
the `voice` column is left alone.

**For V.2.** Call `voice_fingerprint_store.backfill(db)` before grouping
(it is a no-op when all are done), then `fingerprinted_ratings(db)`. For
the published-book calibration use `voice_fingerprint.fingerprint(text)` on
passages of the lengths `rating_text` produces. Standardise per measure
(some are always 0 for a source, e.g. `second_person_pct`; guard a zero
spread).
