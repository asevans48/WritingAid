## Phase context

Phase F makes the app work for stories that are not novels, **keeping every
story feature**: plot, characters, world, critique, the Improve window, Read
Aloud, the Studio. Agreed with the writer on 26 November 2026 (README
decision 18):

- **Kinds.** A project has a kind, chosen when it is created and changeable
  later: **Novel** (novels and novellas, as today, and the default for every
  existing project), **Video series**, **Podcast**, **Editorial series**,
  **Journalism**.
- **Same shape for every kind.** A project still holds a main manuscript,
  novellas and chapters. A kind changes the words on screen (set by the
  kind, editable per project), which checks and goals apply, and what
  publishing prepares. A chapter is one video, one episode or one part.
- **Nothing a novelist has changes.** A Novel project looks and behaves
  exactly as it does before this phase (rule 11). Every test of today's
  behaviour keeps passing unchanged.
- **Phase F comes after the final sweep (9.1).** Sending anything to a site
  (YouTube and others) stays a later integration (decision 7); this phase
  prepares the material.

## The piece

- **Why:** checks built for fiction mislead in a news article, and a
  genre comparison with novels means nothing for a podcast script.
- **The writer gets:** each kind starts with the checks that fit it.
  - **Novel:** exactly today's.
  - **Video series and Podcast (told stories):** the story checks stay;
    page-only checks (paragraph length on the page, manuscript format)
    step back; the spoken checks of F.5 and F.6 come in when built.
  - **Editorial series and Journalism:** fiction-only checks (show don't
    tell, dialogue craft, the genre comparison with novels, the fiction
    prose profile) start **off**; clarity, grammar, spelling, repetition,
    readability and style stay on. A **house style** choice (none, AP,
    Chicago) is offered where a check depends on it.
  - A true-story video or podcast keeps the story checks: it is a story.
- **The writer stays in charge:** a kind sets the starting switches only.
  Every check can still be turned on or off per project, as today, and
  4.3's "checks earn their place" keeps working per project.
- **One table** in the kinds module says which checks start on for which
  kind (from F.0's table). No check's own code learns about kinds beyond
  reading that table.
- **The quality target** (four in five flags worth acting on, decision 3)
  applies per kind: say in *Outcome* which checks have no measurement yet
  for the new kinds.

## Tests

- A Novel project's checks, switches and flags are unchanged.
- Each kind starts with the table's switches; a switch the writer changes
  stays changed.
- Changing kind does not flip a switch the writer set by hand.
