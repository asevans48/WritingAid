## The piece

- **The writer gets:** the same app with less on screen at any moment. What
  is used while writing stays in view; the rest is one click away, in a
  menu named for what it holds.
- **Four parts. Do them in this order and stop after any one if the session
  runs long; each stands alone.**

**1. The Write screen: 24 buttons become 18, grouped by row.**

- **Decided 24 November 2026.** The table of every button and where it goes
  is under *Build notes* below; build exactly that.
- Three novella buttons become one **Novellas ▾**. The drafts ＋, 🗑 and ↗
  become items of the existing **📄 Draft ▾**; ⇅ Split View stays. The two
  annotation buttons become one **📝 ▾**. Everything else stays where it is.
- Every button keeps its object, its signal and its shortcut. A button that
  moves into a menu is the same action added to a menu, not a copy of its
  code (rule 14: `manuscript_editor.py` gets call lines only).
- **A one-time note** on first open after the update says where the six
  moved buttons went.

**2. The hover card on a flagged word.**

- Today: up to five fixes, the "Fix all N like this" box, then up to six
  links (Suggest in context, Ask, Rewrite with AI, Add to dictionary, See
  all N…, Ignore).
- After: the fixes, the box, **Ignore**, and **More ▾** holding the other
  links. "Add to dictionary" stays in view for a spelling flag, since it is
  the commonest answer there.
- The card must still stay open while the pointer is on it or on its menu,
  and ticking the box must still not close it (tests exist in
  `tests/test_fix_all.py`; keep them passing).

**3. The Companion opens what fits the chapter's stage.**

- Today its 7 sections compete for space. After: **Next fixes** is open; so
  is the section that matches the chapter's stage (`chapter_stages.stage_of`);
  the others are collapsed, each still one click away with its count in the
  header.
- **The writer's own choice wins.** A section the writer opened or closed by
  hand stays that way (the state is already stored per section in
  `companion_state`; a hand-set state is never overridden). The stage only
  sets the starting state of sections the writer has never touched.
- No section is removed and nothing new is stored beyond what
  `companion_state` holds today.

**4. Drafts joins File.**

- The menu bar has 7 menus; Drafts has 3 items. They become a **Drafts**
  submenu of File, with the same items, the same shortcuts and the same
  actions. 7 menus become 6.
- If any documentation or tooltip says "Drafts menu", update it to
  "File ▸ Drafts".

- **Rule 13:** this piece adds two menu buttons (Novellas ▾, 📝 ▾) and one
  menu on the hover card, and takes away eight visible buttons, about four
  visible links and one top-level menu. Record the counts before and after.
- **Done when:** the harness shows the Write screen at 18 visible buttons,
  the menu bar at 6 menus, the hover card at no more than three links;
  every action on the checklist is reachable and calls the slot it called
  before.

## Nothing cut, nothing lost (applies to every item above)

- **No feature is removed.** The piece starts with a capability checklist:
  every button, link, menu entry and shortcut on each screen it touches, and
  where each is afterwards. Nothing is ticked off as "gone". An action that
  moves is at most one click further away, and its keyboard shortcut and its
  old menu entry still work.
- **Display only.** This piece changes what is shown and where. It does not
  change `save_project`, `load_project`, the chapter files, or any stored
  file's names, places or layout (rule 15). Text still reaches a chapter
  only through the editor's existing path.
- **Updating is safe in both directions.**
  - A project, settings file or window layout written by the version before
    this piece opens after it with nothing missing and no prompt.
  - Settings keys that are no longer used are left in place and ignored,
    never deleted or rewritten, so going back to the older version of the
    app finds everything as it left it.
  - Any new setting has a default that reproduces today's behaviour for an
    existing project or an existing install, unless the brief says the
    writer chose otherwise.
- **Proof, not promise.** Before and after: the safety check from
  [0.3](03-0.3-safety-net-for-your-two-projects.md) on both of the writer's
  projects (run on copies; tests never touch real work), and the harness
  counts. A test opens a project and a settings file saved before the piece,
  and checks that the chapter text is byte-for-byte the same after open,
  save and reopen.

**Part 1: the Write screen, 24 visible buttons become 19** (new `src/ui/write_toolbar.py`):

- **Novellas ▾** holds ＋ New novella…, ⇢ Move main chapters into a novella… and 🗑 Drop a novella….

- **Changed from the brief's table:** ＋, 🗑 and ↗ went into a new **Drafts ▾**, not the chapter's **📄 Draft ▾**. That menu holds the *chapter's* saved drafts; these buttons act on *manuscript* drafts, and mixing the two would mislead. The result is 19 buttons, not the table's 18.
