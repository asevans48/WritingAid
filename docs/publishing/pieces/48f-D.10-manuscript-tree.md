## The piece

- **Why:** the Write screen spends a whole row at the top on the manuscript
  tabs ("📖 Main Manuscript", one tab per novella) and **Novellas ▾**. The
  chapter list on the left shows only the open manuscript. Two places do
  one job, and the row costs height at 1024 × 600.
- **The writer gets** one tree in the left panel, always shown, even with
  no novellas:

  ```
  Chapters
  ▾ 📖 Main Manuscript        (12)
      1. The Storm
      2. The Pier
  ▸ 📘 The Fall               (5)
  ▸ 📘 Ash Wardens            (3)
    ＋ New novella…
  [ + ] [ ↑ ] [ ↓ ]
  ```

  - **The open manuscript is expanded** and the others are collapsed.
    Clicking a manuscript row opens it, as its tab did. Clicking a chapter
    under another manuscript switches to that manuscript and opens the
    chapter. Use the same switch the tabs use (`_on_subproject_tab_changed`
    and its about-to-switch and switched signals), so saving the outgoing
    manuscript works exactly as today.
  - **Right-click on a manuscript row:** every entry of today's novella tab
    menu (`_show_subproject_tab_menu`): critique, project critique,
    continuity across novellas, rename, turn main into a novella,
    description, move main chapters, drop novella, new novella.
  - **Right-click on a chapter:** today's menu unchanged, plus **Move to ▸**
    (each other manuscript, and "A new novella…").
  - **Drag and drop:**
    - Drag a chapter within its manuscript to reorder it, the same as
      ↑ / ↓.
    - Drag a chapter onto another manuscript row, or between its chapters,
      to move it there: main → novella, novella → novella, novella → main.
    - Several selected chapters can be dragged at once.
    - Dropping a manuscript row onto another does nothing.
  - **＋ New novella…** is a row in the tree. The **+** button still adds a
    chapter to the open manuscript.
- **Taken away:** the top row of manuscript tabs and **Novellas ▾** (one
  button and three menu entries; every entry has a home above). The
  "Editing: Main Manuscript | Drafts ▾ | Split View" row stays: it holds
  the manuscript's *drafts*, a different thing.
- **The old row:** it is behind a switch during the trial (Settings ▸
  Features, beside the Improve window switch; on means the tree). It is
  retired with the other old screens once the writer has checked
  everything (the writer, 26 November).

## Moving a chapter (rule 15: nothing overwritten, nothing lost)

Today only the whole main manuscript moves into a novella
(`_move_main_into_existing`, `_turn_main_into_novella`). Moving **one
chapter** between manuscripts is new. Build it once, in the new module, and
use it for drag-and-drop and Move to ▸ alike.

- Use what the whole-manuscript move does for files, notes and state (read
  it first, and R.7's *Outcome* on chapter folders). A chapter's files
  are **moved, never copied and deleted**. If a name is taken in the
  target, add a number; never overwrite.
- What travels with a chapter: its text, its saved drafts and copies,
  notes, marks, annotations and any per-chapter state. List each in
  *Outcome* and say how it is kept.
- **Chapter ids:** if the target already has a chapter with the same id,
  give the moved chapter a new one, and update everything that refers to
  it.
- **The open chapter:** save it first. After the move, open the chapter
  where it now is.
- **Undo:** after a move, a status-bar line "Moved “The Storm” to The Fall
  · Undo". Undo is the same move back to the same place. There is no
  question before a move: the drop is deliberate, and Undo is there.
- **If anything fails part-way,** put back what moved and say so in a box
  (a failure must not be missed).
- Plan-side data (the outline, beats, continuity) that names chapters:
  check what refers to a chapter by manuscript, and keep it pointing at the
  chapter.

## Build notes

*26 November 2026.*

- **Folder names follow the place.** A chapter folder is `chapter_NNN` by
  its number, and loading a project renames a folder whose name does not
  match its number. So a moved chapter takes the name for its new place,
  and the chapters after it in both manuscripts are renamed as ↑ / ↓ do.
  "A taken name gets a number" therefore means a folder *no chapter uses*
  sitting at a needed name: it is kept as `chapter_NNN_2` (`_3` …), never
  written over, and Undo gives it its name back. A folder belonging to a
  chapter is never touched by another chapter's move (checked before
  anything moves).
- **Moved, not copied.** Every folder goes by `os.rename`, first to a
  temporary `_moving_…` name in its own folder, then into place, so two
  chapters can never meet at one name. The whole-manuscript move still
  copies and checks (it was not changed).
- **The old chapter menu is reused, not copied.** The tree opens the
  chapter list's own right-click menu for the chapter (the hidden list is
  told for a moment which row was clicked and where), so it stays the same
  menu; *Move to ▸* is added by one call line in it, only with the tree on.
  The manuscript row's menu is rebuilt in `manuscript_tree.py` with the
  same entries and methods as the tab's; a test checks the two list the
  same entries for main and for a novella.
- **Reorder by drag uses ↑ / ↓ themselves**, step by step, so it matches
  them exactly (folders, numbers, saves).
- **No move while a draft is being edited** ("Editing:" set to a draft):
  a box says to switch back. Drafts keep their own copies.
- **Undo** sits on the main window's status bar as a button beside the
  message, for 30 seconds or until another message replaces it. With no
  status bar (a separate window), the line appears under the tree.
- **The 150% render** was already 9 px too wide before this piece
  (969 × 600 needed on a 960 × 600 screen). It is now 971: in the offscreen
  renderer, creating any `QTreeWidget` changes emoji widths by 1–2 px on
  the chapter toolbar (shown by building a bare tree instead of this one).
  It is not the tree's own width; the left panel's minimum is unchanged.
- **`tests/test_show_less.py`**: its 19-button count measures D.7's
  arrangement, so it now switches the tree off first (one line, with a
  comment). Nothing else in existing tests changed.

**What travels with a moved chapter** (and how it is kept)

- Its folder, renamed into place: every saved draft (`revision_NNN.md`),
  its saved copies (`backup_*.md`), its outline (`plan.md`), anything else
  in it.
- In the project file (the chapter's own entry, moved to the new
  manuscript): text, title, drafts list, outline and planning (events,
  notes, to-dos, subplot notes, feedback), annotations.
- In `<project>.readiness.json`, from the old manuscript's part to the
  new one's: readiness results and stage, digest, style-sheet facts,
  draft-beside-plan corrections. An entry already there is not written over.
- In `<project>.companion_state.json` (kept by chapter id, so it stays
  with the chapter): last opened, where you stopped, heard marks. After an
  id clash it is copied to the new id.
- Plan-side data: the story-level plot, beats and continuity do not name
  chapters; a character's per-chapter reading names the chapter's id, and
  after an id clash those with the moved chapter's title follow it.
- Proofreading is kept by paragraph text, so it follows the words.
- Manuscript drafts (Drafts ▾) are copies of a whole manuscript and stay
  with the manuscript they were made from.

**Undo and rollback.** Undo moves each chapter back to its old manuscript and
place, with its old id; a folder kept aside gets its name back; if the
state files are as the move left them, they are put back exactly. Tested:

main → novella, novella → novella, novella → main and several at once. A
failure part-way (a rename, a state file, the save) undoes every rename in
reverse and restores the chapters and state files; the project file is
written only at the end.
