## The piece

- **Why:** the app has ten top-level tabs, a right-hand panel with four tabs
  (Planner, Style, Feedback, Companion), a sidebar with two more, about eighty
  menu actions in the manuscript editor, and several windows that list
  problems or offer rewrites. The plan must end with fewer of these, not more.
- **Do:**
  - List every screen that shows problems or fixes, what each shows, and where
    they overlap.
  - Record the counts rule 13 needs: tabs, panel sections, right-click items
    and visible buttons on each main screen. This is the baseline.
  - Confirm or correct the layout in [look-and-feel.md](../look-and-feel.md): scorecard for where,
    Companion for what next, one Improve window for how. Name what merges
    into each and what is retired.
  - Propose a grouping of the ten top-level tabs into about six, for example
    Write, Story (Plot, Characters, World), Revise (Critique with the
    scorecard), Publish (Publishing, Attributions, Prose Profile) and Studio
    (Visuals, Video). This grouping was drafted without reading what every
    tab does, so treat it as a starting point to correct.
- **Also record:** which screens can be detached into their own windows today,
  since the grouping must keep that; and what the Publishing tab
  (`src/ui/agent_manager_widget.py`) and the Feedback tab already do, since
  pieces 1.1, 9.2 and 9.3 should build on them.
- **Also record:** the overlap between `ProWritingAnalyzer` and
  `style_checks.py`, which appear to measure some of the same things twice
  (input to R.4).
- **Where the results go:** the baseline counts and the list of screens go in a
  new file, `docs/publishing/screens.md`. The proposed layout and tab grouping
  go in this file's *Outcome* for the writer to agree. Once agreed,
  [look-and-feel.md](../look-and-feel.md) and pieces D.1 to D.4, 2.1 and 3.2
  are updated to match.
- **Done when:** `screens.md` exists with the counts, and the proposal is
  written down for review.
