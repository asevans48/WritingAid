## The piece

- **Why:** the app has ten top-level tabs, a right-hand panel with four tabs
  (Planner, Style, Feedback, Companion), a sidebar with two more, about eighty
  menu actions in the manuscript editor, and several windows that list
  problems or offer rewrites. The plan must end with fewer of these, not more.
- **Do:**
  - List every screen that shows problems or fixes, what each shows, and where
    they overlap.
  - Record the counts rule 13 needs: tabs, panel sections, right-click items
    and visible buttons on each main screen. This is the baseline.
  - Confirm or correct the layout in [look-and-feel.md](../look-and-feel.md): scorecard for where,
    Companion for what next, one Improve window for how. Name what merges
    into each and what is retired.
  - Propose a grouping of the ten top-level tabs into about six, for example
    Write, Story (Plot, Characters, World), Revise (Critique with the
    scorecard), Publish (Publishing, Attributions, Prose Profile) and Studio
    (Visuals, Video). This grouping was drafted without reading what every
    tab does, so treat it as a starting point to correct.
- **Also record:** which screens can be detached into their own windows today,
  since the grouping must keep that; and what the Publishing tab
  (`src/ui/agent_manager_widget.py`) and the Feedback tab already do, since
  pieces 1.1, 9.2 and 9.3 should build on them.
- **Also record:** the overlap between `ProWritingAnalyzer` and
  `style_checks.py`, which appear to measure some of the same things twice
  (input to R.4).
- **Where the results go:** the baseline counts and the list of screens go in a
  new file, `docs/publishing/screens.md`. The proposed layout and tab grouping
  go in this file's *Outcome* for the writer to agree. Once agreed,
  [look-and-feel.md](../look-and-feel.md) and pieces D.1 to D.4, 2.1 and 3.2
  are updated to match.
- **Done when:** `screens.md` exists with the counts, and the proposal is
  written down for review.

### Found along the way

- **Right-click is smaller than the brief thought:** 12 items without a
  selection, 22 with one, not about eighty. The eighty counts every menu
  action in the editor file.
- **Cut and Copy never appear in the right-click menu** (a selection check on
  the wrong cursor). For D.1.
- **The flag right-click menu in `EnhancedTextEditor` is unreachable in the
  Write tab,** but the hover card offers all of its actions. The Checks
  menu tooltip still tells the writer to right-click. For D.1.
- **Publishing's three action buttons are placeholders** that say "will be
  implemented soon". The working exports are in the Export menu. For 9.2 and
  9.3.
- **Feedback → Analyze with no model shows a warning,** which breaks rule 1.
- **Critique and the Style tab count style issues differently,** because
  they use different analysers (table in screens.md). For R.4.

### Proposed layout: confirm or correct

look-and-feel.md's three roles hold up. Corrections and what moves where:

**Scorecard: *where* the work is** (the front page of the Critique tab, 2.1)
- Folds in the six **Analyze ▾** analyses. Each becomes a report choice in the
  Critique, so its result is saved, rated and kept in history, which the
  separate windows are not. The Analyze ▾ entries stay as shortcuts that run
  the matching report, so nothing a writer can do is lost.
  `ProseAnalysisDialog` and `PromiseCheckDialog` are retired after a trial.
- The **Review** menu stays as it is. It already only starts the Critique.
- **Correction:** the Critique has 11 report types plus an Overdescribed tab,
  not a single report. The scorecard sits above them; it does not replace
  them.

**Companion: *what next*** (D.3, 3.2)
- Folds in the **Style** tab's list of issues. The side panel goes from 4
  tabs to 3: Planner, Companion, Feedback.
- **Today's three fixes** and **Overly descriptive** become the Next fix
  card, taking the Companion from 7 sections to 5 (look-and-feel point 7,
  confirmed: it has seven today).
- **Correction to look-and-feel point 3:** "the Style tab's on and off
  switches become a small control on the editor". That control already
  exists: it is the ✓ Checks ▾ menu, which turns spelling, grammar, overuse
  and style on and off. What has to move into it is only the Style tab's
  switches for each of its eleven checks, as a submenu. No new control is
  needed.
- **Feedback** stays its own side-panel tab for now. It is the writer's input
  (notes from readers and editors), not a list of problems. 3.2 can later
  turn entries into queue items.

**One Improve window: *how*** (D.2)
- Rephrase, Suggestions and Overly descriptive? become tabs of one window,
  as planned. Confirmed: they share the same layout and already share the
  conversation panel (`rewrite_chat_panel.py`) and `OverdescriptionPanel`.
- **Left as they are, for the writer to decide:** AI Thesaurus (one word,
  quick) and Ask (a conversation about one flag). Each could become a fourth
  or fifth tab later. Folding them in now would make D.2 larger than M.
- **The right-click menu (D.1):** its three Improve entries (Rephrase,
  Suggestions, Overly descriptive?) become one "Improve this…". AI Thesaurus
  stays. Selection items: 11 top-level entries down to 9, and Cut and Copy
  fixed so that they show.

**Consistency** keeps its entries in the Review, Checks and Analyze ▾ menus
as shortcuts. Only the Style tab's button goes, when that tab folds in.

### Proposed tab grouping: ten into five

| Group | Holds | Why |
|---|---|---|
| **Write** | Write | unchanged |
| **Story** | Plot, Characters, World | as drafted |
| **Revise** | Critique (with the scorecard), Prose Profile, Attributions | **Corrected.** Prose Profile holds the genre, tone and voice targets that the critique and rewrites measure against, so it belongs with revising, not publishing. Attributions is the list of every annotation (notes, attributions, recommendations) across the chapters, which is revision material. |
| **Publish** | Publishing | Agent contacts. Its publish buttons are placeholders today; 9.2 and 9.3 build the submission package here. |
| **Studio** | Visuals, Video Studio | as drafted |

That is 10 top-level tabs down to 5. The draft put Attributions and Prose
Profile under Publish; reading the code says otherwise.

**Detaching must keep working (D.4).** Today any top-level tab can be
detached, in Multi-Window Mode. After grouping, each of the ten screens must
still be able to go into its own window, not only the groups. D.4 should let
the writer detach either a whole group or one screen inside it, using the same
right-click → Create New Window.

### Agreed

The writer agreed:

- the simplest interface possible that is still intuitive, **without cutting
  any feature**, and backwards compatible;
- menu entries stay as shortcuts;
- the Analyze ▾ change, the Companion change and the Improve window merge;
- the tab grouping above.
