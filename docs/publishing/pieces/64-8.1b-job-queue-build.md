## The piece

- **This session: build to the design agreed in 8.1a.**
- **The writer gets:** long reads run as a job that keeps going with the window
  closed, shows its progress, can be paused, and resumes after a restart.
- **Build:** one job type to start with, the whole-book check from 2.3.
- **Tests:** a job interrupted half-way resumes from the next chapter; a server
  that goes away pauses the job with a clear message.
- **Done when:** a whole-book check started in the evening is finished in the
  morning.

## What has changed since this brief was written

_Added 24 November 2026, after phase 3, D.3 and 2.5 were built. Read the Outcome of each piece named here._

- **The on-device model cannot be shared.** A model job started while the
  app was using the on-device model crashed the app (a Metal GPU timeout).
  The design must say how a job and the live app take turns: one queue for
  every model call, or jobs only on the server. A job must never start a
  second on-device run.
- **Crashes leave a trace now:** `~/.creativeos/crash.log`
  ([0.5](03c-0.5-crash-log-and-safe-clicks.md)). A job that dies should say so there.
- **Added 26 November 2026 by 8.1a.** The design is written: build to
  [8.1a's *Design*](63-8.1a-job-queue-design.md#design) (the job file
  `<project>.jobs.json`, §3; the modules `job_store`, `book_check_job`
  and `job_queue`, §14; the 21 tests, §16), once the writer has answered
  its open questions (§17; checklist section 3, "8.1a: review the
  job-queue design").
