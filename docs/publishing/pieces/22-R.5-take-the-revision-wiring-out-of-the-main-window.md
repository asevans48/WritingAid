## Phase context

Each of these changes no behaviour. They are placed where they make the next
feature pieces smaller and safer. All keep old import paths working and pass
the existing tests unchanged.

## The piece

- **Why:** `main_window.py` is over 15,000 lines. The scorecard, the queue and
  the Improve window all need to open a chapter, find a sentence and hand it
  to a tool. That wiring should not add to the file.
- **Do:** a small controller module that owns "open this chapter at this
  sentence and show this tool", used by the critique tab, the Companion and
  the scorecard. Move the existing handlers that do this (for example
  `_expand_critique_statement`) into it.
- **Limit:** only the revision wiring. This is not a general split of the main
  window.
- **Done when:** the handlers live in the controller, the main window is
  shorter, and pieces 2.2 and D.2 can call the controller.

- **Data safety:** the main window is where the editor's text is carried into
  the project and saved, including the guard against saving a chapter as
  blank. This piece does not touch that. When the controller opens a chapter,
  it goes through the existing chapter-switch path, so the chapter being left
  is flushed and saved exactly as today. It moves no save, load, autosave or
  close-down code. Add a test: with unsaved edits in one chapter, opening
  another through the controller keeps those edits.
