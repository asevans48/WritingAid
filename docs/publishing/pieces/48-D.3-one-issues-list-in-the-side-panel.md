## The piece

- **The writer gets:** the right-hand panel goes from four tabs to three
  (Planner, Companion, Feedback). The Style tab's list of issues becomes the
  line stage of the Companion's queue. Its switch for each of the eleven
  checks moves into the existing **✓ Checks ▾** menu on the editor toolbar,
  as a "Style checks" submenu. That menu already turns spelling, grammar,
  overuse and style on and off. No new toolbar control is added (agreed in
  0.2).
- **Read first:** `src/ui/style_panel.py`, the right panel set-up in
  `src/ui/manuscript_editor.py`, and the Checks menu set-up in
  `ChapterEditor` (same file).
- **Settled in 0.2:** the Feedback tab stays its own tab. It holds the writer's
  notes from readers and editors, which are input, not a list of the app's
  findings, so it does not overlap the Companion's notes.
- **Capability checklist** (everything the Style tab does today, and where it
  goes):
  - counts per check → queue section header, and the Checks submenu;
  - toggle each check's highlighting → Checks → Style checks;
  - step through issues → the queue;
  - apply the suggested fix → the queue's Accept;
  - ✨ Rewrite with AI → the queue, opening the same rewrite;
  - Ignore → the queue's "Not a problem" (3.3), or Ignore until 3.3 is built;
  - open Consistency → still in the Checks menu, the Analyze menu and the
    Review menu.
- **Shortcuts stay:** "Style issues panel…" in the Checks menu opens the
  Companion on the queue once the Style tab is retired.
- **Done when:** every style issue can be reached and fixed from the queue and
  the highlight switches work from the toolbar. The Style tab stays until you
  agree to retire it; it then goes with a one-time note saying where it went.

- **Data safety:** issues the writer has marked as ignored, and the style sheet
  rules behind them, are read from where they are today and still honoured.
  The highlight switches keep their saved state.

## Outcome

**Status:** built; the Style tab stays until the writer agrees to retire it.
Tests: `tests/test_next_fixes.py` (D.3 section).

**Every style issue is in the queue.** The queue's line stage already held
the readiness line checks (adverbs, passive, filler and wordy, clichés,
echoes, sticky sentences, preference breaks at copyedit). The three Style
tab kinds no check reports (`repeated_start`, `long_sentence`,
`hard_sentence`) now come from the editor's live style flags, with the
writer's switches and ignores applied (`fix_queue.STYLE_ONLY_KINDS`,
`style_entries`; `Queue._style_flags`). Tested: everything the Style tab
lists is in the queue.

**Capability checklist:**
- **counts per check:** the Next fixes header count, and the Checks submenu
  ("Adverbs (3)", counted as it opens).
- **toggle each check's highlighting:** ✓ Checks ▾ → Style checks.
  **New `src/ui/style_checks_menu.py`**, one call line in
  `manuscript_editor.py`. The Style tab's boxes follow the menu; the menu
  reads the editor's state each time it opens.
- **step through issues:** the queue (Skip, back, keys).
- **apply the suggested fix:** Accept.
- **✨ Rewrite with AI:** for a style finding, the card's 💡 More options… sends
  the Style tab's own rewrite request (`style_rewrite_requested`, the
  sentence, "Fix the adverbs: …"); for others it opens Suggestions, as before.
- **Ignore:** Not a problem (3.3). For a live style flag this is the Style
  tab's Ignore (`ignore_style_issue`); Undo puts it back.
- **open Consistency:** unchanged (Checks menu, Analyze, Review, the Style tab).

**Counts:** Companion unchanged (sections 7, buttons 15). The Write screen's
Checks menu goes from 29 to 40 items: the eleven style switches the brief
moves there. When the Style tab is retired its 15 buttons go, and "Style
issues panel…" will open the Companion on the queue with a one-time note,
as the brief says. The panel stays at four tabs until then.

**Left out:**
- The switches were never saved, so there was no saved state to keep. Each
  editor starts with every style check on, today and now.
- Retiring the Style tab waits for the writer's agreement.
