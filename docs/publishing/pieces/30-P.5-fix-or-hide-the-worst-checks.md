# P.5 Fix or hide the worst checks

| | |
|---|---|
| **Size** | M, repeatable |
| **Phase** | Phase P. Parity with ProWritingAid |
| **Depends on** | [Q.2](10-Q.2-scoring-the-checks.md) |
| **Status** | Not started |

**Before you start, read:** [the rules](../README.md#rules-every-piece-follows); the *Outcome* section of each piece this one depends on; [what already exists](../inventory.md).

## The piece

- **Do:** take the two or three worst checks from the Q.2 table. For each,
  either improve it until it meets the target, or turn it off by default and
  say why.
- **Existing projects:** a check is never switched off in a project that already
  exists. The new default applies to new projects; an existing project is told
  once that the check is unreliable and offered the choice.
- **Improving a check changes what is flagged.** Show the before and after
  counts on the benchmark so the change is deliberate.
- **Repeat** whenever the table changes: after P.1, P.2 and P.4.
- **Done when:** every check that is on by default meets the target.

## What has changed since this brief was written

_Added 24 November 2026, after phase 3, D.3 and 2.5 were built. Read the Outcome of each piece named here._

- **Use the miss measurements too,** not only the Q.2 table:
  [miss_rates.md](../miss_rates.md), from `scripts/measure_misses.py`. The
  report now lists examples of flags raised on untouched passages, labelled
  by source (the model, a rule the model kept, or a rule).
- **First candidates, from those examples:** British spellings flagged as
  misspellings ("marvellous"), archaic words ("bloweth", "listeth"), proper
  names ("Agathon") and word fragments ("un").
- **Unexplained so far:** with the model, clean passages get more flags (11.9
  per 1,000 words) than with the rules alone (8.93). Rerun
  `venv/bin/python scripts/measure_misses.py --model --editor --limit 3 --cases 4`
  with the app closed, and work from its examples.
- **Already fixed, do not redo:** the model can no longer clear a rule that
  is right whenever it fires. `SURE_RULES` (doubled word, spacing,
  lowercase "i") and `NARRATION_SURE_RULES` (agreement, outside dialogue) in
  `src/ai/readiness_judge.py`. The proofreader restores a rule flag the judge
  cleared when it finds the same mistake (`proofread.add_findings`).
- **A check that is hidden** must also leave the next-fix queue
  (`src/ai/fix_queue.py`) and the Write menu's Style checks submenu
  (`src/ui/style_checks_menu.py`).
- **Never run the model while the app is using the on-device model.** A
  background run once crashed the app (Metal GPU timeout). Ask the writer to
  close the app, or use the rules-only run.
- **Added 24 November 2026 by P.2a.** Four more style checks exist (Few
  transitions, Pronouns, Alliteration, Acronyms), all off until ticked.
  Few transitions and Alliteration are below 4 in 5 on the marked set
  (their misses are deliberate choices, not wrong detections); see
  [P.2a's Outcome](31-P.2a-missing-reports-transitions-pronouns-alliteratio.md#outcome).
  `check_scores.md` gets their rows on the next `score_checks.py` run.
- **Added 24 November 2026 by P.3.** Where the book's genre has figures
  from published books (`~/.creativeos/genre_baseline.json`, built by
  `scripts/genre_baseline.py`), the adverbs and passive voice thresholds
  come from `genre_baseline.threshold`, not `THRESHOLDS`. Retuning those two
  in `THRESHOLDS` changes only projects whose genre has no figures. If a
  check's counting changes, rebuild the baseline too, since it is measured
  with the checks' own code; see
  [P.3's Outcome](33-P.3-every-measure-compared-with-the-genre.md#outcome).

## Build notes

_Added 24 November 2026 so a fresh session can finish this piece without searching. Names were checked against the code on that date; if one has moved, find it with a search and say so in Outcome._

- **Read first:** [check_scores.md](../check_scores.md) and
  [miss_rates.md](../miss_rates.md); `scripts/measure_misses.py`;
  `src/ai/readiness_judge.py`; `src/utils/proofing.py` (the spelling and
  grammar engines); the check's own module under `src/ai/readiness_checks/`.
- **How to choose:** the two or three checks with the lowest share of right
  flags, then the kinds of false flag in the clean-passage examples.
- **For the spelling false alarms** seen so far (British spellings, archaic
  forms, proper names, fragments): look first at whether the project's
  language variant and its names reach the spell checker
  (`set_project_vocabulary`), before changing the checker.
- **Run the measurement without a model** unless the writer has closed the
  app: `venv/bin/python scripts/measure_misses.py --limit 3 --cases 4`.
- **"Told once and offered the choice"** for an existing project: a line in
  the Critique (not a dialog), stored in `readiness_state` so it is not
  shown again.
- **Tests:** the benchmark numbers before and after in *Outcome*; a project
  created before the change still has the check on; a new project gets the
  new default.
- **Stop and report if** improving a check lowers what it catches on the
  seeded mistakes.
