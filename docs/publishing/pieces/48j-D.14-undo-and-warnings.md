## The piece

The writer's answers (27 Nov): "Keep the chapter deck editor. Undo should
remove the empty novella. 30 seconds is fine but it would be better to keep
it after the first save. Fix the bugs and add a warning."

1. **The chapter-deck editor stays** (for F.10). Nothing to build; a line
   in its module's docstring says why it is kept with no way in.
2. **Undo removes the empty novella.** After "Turn main manuscript into a
   novella…", Undo puts the chapters and drafts back **and** drops the
   novella it made, if it is still empty (nothing added to it since).
   Nothing is deleted from disk that held anything (rule 15); if the
   novella is no longer empty, Undo leaves it and says so. Update the
   question's wording to match ("…puts the chapters and drafts back and
   removes 'Novella 1'").
3. **Undo lasts until the next save.** The status bar's Undo still goes
   after 30 seconds, as now. The last move also stays undoable from the
   tree: right-click ▸ "Undo the last move (…)" until the project is next
   saved (by the writer, or autosave if there is one: find out and say
   which in the wording), the next move, or the app closing. The questions
   from D.12 say this in plain words, accurately. Applies to every D.10 move
   that offers Undo, not only the whole-manuscript ones, unless that would
   be wrong for one of them (report it).
4. **Fix the bugs** (rule 15):
   - Video Studio: removing a scene action or one of its images deletes the
     image files at once, even if the dialog is then cancelled. Files are
     removed only when the change is kept (or never, if they might be used
     elsewhere); cancelling leaves everything as it was.
   - Checkpoint restore: a failed restore says "Your project is unchanged"
     although the folder was emptied first. Restore so that a failure
     really leaves it unchanged (unpack beside it, then swap), or, if that
     can't be done safely, say exactly what happened and where the copy is.
   - Wrong wordings: Plot's Remove tension / Remove theme ("You can re-add
     it later") and Consistency ▸ Change all (claims every change can be
     undone; only the open chapter's can). Make each say what is true.
5. **Add a warning to the deletes** in D.12's list (World's Remove buttons
   and map Delete, Plot's timeline Delete / Remove subplot / Remove
   promise, Characters' removes, the Companion's Story memory, style-sheet
   rule and note removes, the Planner's deletes, Feedback delete, the
   Critique's context Clear, the Studio's Remove take and card / slide
   element deletes): before each, one plain question naming the item and
   saying it can't be undone, with the safe answer as the default button.
   One shared helper (for example in `ui_kit`) so every warning looks and
   reads the same. A small item inside a list the writer is editing (for
   example one bullet in an open editor that has its own Cancel) needs no
   warning if Cancel already brings it back: report such cases.
   - Follow D.9: these are questions about deleting, so they stay boxes.

### 3. Undo lasts until the next save ✓

**Autosave, found out:** the app autosaves after every move, every chapter
switch and novella switch, and after most edits (`_auto_save_project`), so
"until the next save" counting autosaves would end Undo at once. It counts
**only the writer's own save**: File ▸ Save Project, Ctrl+S, the toolbar's
Save, the tray's Save Project and Save As (all through
`MainWindow._save_to_path`, which now has two call lines:
`manuscript_tree.forget_last`). The words say so.

The status bar's Undo is unchanged (30 s, `NOTICE_MS`; it goes when another
message replaces it). The last move also stays as a right-click entry,
**"Undo the last move (3 chapters to Novella 1)"** (what moved, and where),
on any manuscript row and in a chapter's menu just under Move to ▸, until
the writer next saves, the next move, another project is opened (the move
belongs to the project it was made in), or the app closes. It applies to
every D.10 move with Undo (drag, Move to ▸, Move main chapters, Turn main
into a novella); none was wrong for it, since Undo is the same move back,
chapter by chapter, and skips a chapter that is gone. While "Editing:"
shows a draft, Undo says to switch back first (as every move does) and
stays available. The entry is only there when there is a move to undo, so
no count rises.

The new words (`undo_note`, every question before a whole-manuscript move;
`N`, the names and the drafts parts filled in as before):

> Undo, on the status bar for 30 seconds (until another message replaces
> it), puts the chapters and drafts back and removes “Novella 1” (unless
> something has been added to it since). It is also on the manuscript
> tree's right-click (“Undo the last move”) until you next save the project
> yourself (Save Project, Ctrl+S; the app's own autosaves don't count), make
> another move or close the app. After that you can still move the chapters
> back (right-click ▸ Move to), but the drafts stay with “Novella 1”.

(For an existing novella: "…puts the chapters and drafts back." with no
"removes".) *Chapters Moved* now ends: "Undo is on the status bar for 30
seconds, and on the manuscript tree's right-click until you next save the
project yourself (Save Project, Ctrl+S; the app's own autosaves don't
count), make another move or close the app."

### 4. The bugs (rule 15) ✓

- **Video Studio images.** Found out first: neither the scene editor nor
  the action editor has a real Cancel (Close, Esc and the window's ✕ all
  keep the changes, by an earlier writer request), so the files went at
  once while the change was always kept; the real danger was that the same
  picture can be used elsewhere (another action, a slide deck seeded from
  the favourite). Now removing an action (`scene_editor._on_remove_action`)
  or one of its images (`scene_action_dialog._on_delete_image`) only notes
  the files; they are deleted when the window closes with the change kept
  (`done`), and only if nothing else in the Studio names the file (same
  path or same file name: `src/video_studio/pending_removals.py`,
  `still_used`). A file still used, or any file when the Studio can't be
  read, is kept. A close that keeps nothing deletes nothing. Both now ask
  first (below).
- **Checkpoint restore** (`src/services/project_checkpoint.py`,
  `_swap_in`). The archive is unpacked beside the project first (a hidden
  folder inside `_checkpoints/`, same disk); a failure there (damaged zip,
  full disk) leaves the project untouched. Then the project's entries are
  renamed aside and the unpacked ones renamed in; if a rename fails, every
  entry is put back. Only after that is the set-aside copy removed (the
  "Before restore" checkpoint holds it, as before). If putting back fails
  too (`RestoreIncomplete`), the box says exactly what happened and where
  each part is ("…The project's own files that were not put back are in
  …/_checkpoints/.before-restore-…; the unpacked checkpoint is in
  …/_checkpoints/.restore-…", then: "The "Before restore" checkpoint holds
  the project as it was before you chose Restore."). Otherwise *Restore
  failed* says "Could not restore the checkpoint: … Your project is
  unchanged." and that is now true. A Video Studio folder the checkpoint
  doesn't hold is still left alone. (`project_checkpoints_dialog.py`.)
- **Wrong wordings.**
  - Plot ▸ Remove tension / Remove theme: "Remove the tension “…”? ¶ This
    can't be undone." (the shared question; it used to say "You can re-add
    it later").
  - Consistency's hint: "Double-click an occurrence to jump to it in the
    manuscript. Changes apply to every chapter, including ones that aren't
    open. Only the open chapter's changes can be undone (Ctrl+Z in it); the
    other chapters are changed directly, with no undo."
    (`consistency_dialog.py`.)
