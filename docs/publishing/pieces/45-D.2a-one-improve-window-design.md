## Design

_Written 25 November 2026 (D.2a). Waiting for the writer's review; the
open questions are at the end. Names were checked against the code that
day._

### 1. In one paragraph

One window, **Improve**, opens on a passage. It has four tabs along the
top: **💡 Suggestions · ✨ Rephrase · 🔍 Expand · 📝 Critique**. Each tab
has its own small set of options at the top. Below them, everything is
shared: one list of **versions** (from any tab), an editable **Your
version** box, the **changes** from your text, the **rating** row and
**Talk it through**. **✓ Accept** and **Close** sit at the bottom and
never scroll away. Every place that opens Rephrase, Suggestions or Overly
descriptive? today opens this window on the matching tab. Each tab uses
the model it uses today. Ratings go to the same place with the same
values. The old windows stay, unchanged, behind one switch in Settings
until you have tried the new one on both projects.

### 2. The three windows today, and the fourth tab

| Today | Class | Opens | Model | Writes |
|---|---|---|---|---|
| **Suggestions** | `PassageCritiqueDialog` (`src/ui/passage_critique_dialog.py`, 643 lines) | runs at once | `_build_llm`: `build_critique_llm()` or the default | ratings (`log_rated_rewrite`, style `"suggestion"`), accepted expansions (style `"expansion"`), avoided phrases, Story memory |
| **Rephrase** | `RephraseDialog` (`src/ui/rephrase_dialog.py`, 2,516 lines) | waits for Generate | `_init_agent`: default provider and key; a trained `rephrase` task model for local; Python libraries when AI is off; Cloud / Local choice; `_moment_llm` for talk and the scene summary | ratings (`log_rephrase` direct, style `"<style>/<tone>"`, `" \| edited"`, genre, character; a delayed save; a `"neutral"` row for the unedited option), Story memory |
| **Overly descriptive?** | `ExpandStatementDialog` (`src/ui/overdescription_panel.py`) | runs at once | the same `_build_llm` as Suggestions | accepted expansions (style `"expansion"`) |

**Critique** is not a fourth window. It is the "What works / What doesn't
/ Dialogue / Order and flow" part of Suggestions, which today sits in an
inner tab above the rewrites and pushes them below the fold at
1024 × 600 (see the harness picture: at that size the rewrites cannot be
seen without scrolling). It becomes its own tab, filled by the same model
call as Suggestions. No extra model call.

### 3. What is truly shared, and what each tab needs alone

**Shared by all four tabs** (built once, in the lower half):

- The **passage** strip: the text being improved, with overly descriptive
  statements highlighted, the "your highlight was widened" note, and
  **▾ context** (Rephrase's "Show surrounding context").
- The **versions** list. Each row says where it came from: "Suggestion 2 ·
  voice 94%", "Rephrase · concise", "Your text, expanded", "revised: …".
  New versions go to the top, as Suggestions does today. Switching tabs
  does not hide versions, so you can compare a suggestion with a rephrase
  and pick either.
- **Why** and **⚠ notes** for the picked version (Suggestions' why,
  Rephrase's "Style: … | Tone: … — explanation").
- **Your version**: the editable box, with Rephrase's **✏ edited** badge
  and **↺ Reset**, now for every version. **Your edits stay with their
  version**: picking another version and coming back keeps them, so
  nothing needs a "Discard your edit?" question (see open question 6).
- **Changes from your text**: Suggestions' word-level diff, now for every
  version.
- The **rating** row: ★ Excellent · Good · Poor · Bad, 🚫 Avoid a phrase…,
  and one status line ("Saved.", "Saving as good after you finish
  editing…", "Noted. Turn on data collection…").
- **Talk it through**: one slot, holding the conversation of the tab you
  are on (each tab keeps its own, as today).
- **Close** and **✓ Accept**, at the bottom, never scrolled away.
- One **status** line under the tabs for progress ("Gathering characters,
  world and plot…") and messages.

**What each tab needs alone** (its top part):

| Tab | Its own options | Runs | Its versions |
|---|---|---|---|
| 💡 Suggestions | Focus (optional), ↻ Regenerate | when first shown | the three rewrites; revised versions from the talk |
| ✨ Rephrase | Scene (with ↻ Refresh), **Generate options**; a one-line summary of the choices and **▸ Change options** (closed by default, remembers): writing style ×7, tone ×12 + Custom, point of view, character voice (auto-detect), genre, Cloud / Local | when you press Generate, as today | the rephrase options |
| 🔍 Expand | the statement list, the statement, why, hints, ways to expand it, a direction line with **More ideas**, **Apply to passage**, **↺ Keep original** (this is `OverdescriptionPanel` as it is) | when first shown, unless Suggestions already ran it | "Your text, expanded" (every applied expansion) |
| 📝 Critique | none: the critique to read | with Suggestions (one call) | the same versions as Suggestions |

Expand's own small preview (the one statement) stays inside its tab;
**Apply to passage** is its old ✓ Accept renamed in this window only, so
there is one ✓ Accept on screen.

### 4. The window

- Title "Improve — <first words of the passage>". Opens over the window
  you are in: its parent is `widget.window()` of the editor (main window,
  a detached Write window, a draft window). When the Critique in its own
  window sends you to a passage it already brings the main window forward
  (`critique_window`), and the Improve window opens over that.
- Modal, like the three today, so the chapter cannot change underneath.
- Size: `fit_to_screen(1100, 780)`, then `remember_geometry(…,
  "improve_window")`. Everything between the tab bar and the bottom row
  scrolls (`ui_kit.scrollable`); Accept and Close never scroll.
- Narrow (under 1,200 px, `ui_kit.size_class`): Talk it through is a
  closed section under the preview. Normal and wide: it is a third column
  beside the preview, open.
- Built from `ui_kit` only (D.8): Accept is the one `primary_button`;
  every other button `plain`; colours from `PALETTE`; no `#rrggbb`.

All twelve go through one new call, `improve.open(host, tab, …)`, put in
the five methods named above (`_rephrase_selection`,
`_rewrite_span_with_ai`, `suggest_for_span`, `expand_statement`, and the
draft window's `_rephrase_selection`), one line each. Those methods keep
their signatures and return values, so the Companion, the queue, the
Critique and the 👂 marks keep working without change: a return of True
still clears the note, the mark or the fix.

**Whatever tab you accept from counts.** Opened from Suggest fix and
accepted from Rephrase: the note is still cleared.

No new entry is added. AI Thesaurus and 💬 Ask stay their own windows.
Later, Ask could become a fifth tab whose Talk it through is about one
flag, and AI Thesaurus a "Words" tab for a selected word; not now.

### 6. Putting text into the chapter (rule 15)

Each version remembers the span it was made for. Suggestions, Critique and
Expand widen the selection to whole sentences (`expand_to_sentences`), as
today; Rephrase works on the exact selection, as today. The passage strip
shows the widened passage with the selection marked. **✓ Accept** hands
back `replacement`, `span` and `tool`, and the host applies it **through
the call that tool uses today**:

- Suggestions or Critique: `_replace_span(doc_text, start, end, text,
  "Suggestions")`, with its check that the chapter has not changed.
- Expand: `_replace_span(…, "Overly descriptive")`.
- Rephrase: the selection cursor's `insertText(_tidy_replacement(…))`, as
  `_rephrase_selection` and `_rewrite_span_with_ai` do; in a draft window,
  that window's own `insertText` and `_set_dirty(True)`.

Nothing else writes text. The writer accepts every change (rule 5); the
diff is shown for every version; Ctrl+Z undoes it in the editor.

### 7. Ratings, history and the voice-group examples

**Nothing new is stored, and nothing changes where or how it is stored.**
Each version is rated by the tab that made it, through that tab's own
code:

| Version from | Rating click | ✓ Accept | Other writes |
|---|---|---|---|
| Suggestions, Critique, revised, "Your text, expanded" (when Suggestions ran) | `log_rated_rewrite(…, style "suggestion", before/after 500, genre)` at once, as `PassageCritiqueDialog._log` | the rating, or "good" unless Poor or Bad | — |
| Rephrase | `RephraseDialog._on_rating_clicked`: saved 0.9 s after you stop editing, with "edited" | `RephraseDialog._use_selected`: Poor/Bad first, the accepted row, and the `"neutral"` row for the unedited option | — |
| Expand alone ("Your text, expanded" when Suggestions has not run) | `log_rated_rewrite(…, style "expansion")` (open question 5) | — | each applied expansion: `overdescription_panel.log_accepted` (style `"expansion"`), as today |
| any | 🚫 Avoid a phrase: `add_avoid_phrase` (Settings' list, read by Suggestions and Rephrase) | | 📌 Remember / proposed memories: `story_memory.add`, source `"suggestions"` or `"rephrase"` |

All rows go to the one ratings database (`rephrase_database`), which
stamps each with its voice fingerprint (V.1) as now. Only when data
collection is on, as now. There is no other history: Rephrase's
conversation history and Suggestions' turns live only while the window is
open, as today.

**Voice-group examples (V.4).** Each tab still asks
`rewrite_quality.examples_prompt` with exactly the arguments it passes
today (Suggestions: the text before and after; Rephrase: the
surroundings and the detected speaker). The answer's plain words ("from
your voice group “…”" or "from all your ratings") show as the tooltip
on the versions list and the rating buttons for that tab's versions,
where Rephrase and Suggestions each put it today. A project kept to itself
(`ratings_privacy`) behaves as today. No button is added.

### 8. Models (rule 2) and no model (rule 1)

Each tab keeps its own model, resolved by its own code, and the window
never builds one itself:

- Suggestions, Critique, Expand: `passage_critique_dialog._build_llm`
  (the critique task model, else the default), in their workers.
- Rephrase: `RephraseDialog._init_agent` and `_moment_llm`, with its
  Cloud / Local choice (now under ▸ Change options) and its
  Python-libraries mode when AI is off.
- Talk it through uses the model of the tab you are on.

**With no model:** Suggestions and Critique show today's "No AI model"
line plus one more sentence with two links: "Rephrase still works
(simpler rewrites) · Expand shows the word scan". Expand shows the word
scan with "clues, not proof". Rephrase uses the Python libraries, and its
talk regenerates instead, as today. Nothing is empty, nothing raises.

**No wasted model calls.** A tab runs the first time it is shown, never
on every switch. A Suggestions run also fills Expand, as today. If Expand
already ran, Suggestions skips its own review (a new optional
`SuggestionWorker` argument). Rephrase waits for Generate, as today.

### 10. How the code is arranged

- **New, small modules** (rule 14), all from `ui_kit`:
  - `src/ui/improve_window.py`: `ImproveWindow(QDialog)` (passage strip,
    tabs, the shared lower half, Accept, Close, keys, geometry) and
    `Version` (text, label, source tab, span, why, notes, voice fit, the
    source's own data). About 400 lines.
  - `src/ui/improve.py`: `open(host, tab, text, start, end, *,
    selection=None, focus="", instruction="", …) -> bool`, the trial
    switch `merged()` and `set_merged()`, and `apply(host, window)` (§6).
    Also `ImproveOption` for Settings, as D.4's `TabsOption`.
  - `src/ui/improve_tabs.py`: the Suggestions, Critique and Expand tabs.
    Each tab is a small object with `key`, `title`, `widget`, `start()`,
    `rate(version, value)`, `accepted(version, text)`, `talk` (its
    `ConversationPanel`, or None) and a `versions_added` signal.
  - `src/ui/improve_rephrase.py` (D.2c): the Rephrase tab.
- **Shared by calling, not copying.** The tabs reuse `SuggestionWorker`,
  `ReviewWorker`, `MoreWorker`, `OverdescriptionPanel`, `ExpansionState`,
  `log_accepted`, `ConversationPanel`, `run_turn`, `remember`,
  `propose_memory`, `diff_html`, `add_avoid_phrase`. The non-window parts
  of `PassageCritiqueDialog` that the new tab needs (`_discussion_html`,
  `_chat_context`, `_log`, the "expanded version" rule) move to
  module-level functions in `passage_critique_dialog.py`, which the old
  class then calls: a move with no change of behaviour, its tests
  unchanged.
- **Rephrase is hosted, not rewritten** (D.2c). The Rephrase tab holds a
  real `RephraseDialog`, embedded as a widget with a new optional
  argument `hosted=True` that hides its own list, preview, rating row,
  Use and Cancel. Its options and Scene show in the tab; its
  `ConversationPanel` goes in the Talk it through slot. The window
  forwards to it: a picked Rephrase version selects its row in the hidden
  `options_list` (so its delayed save and edit tracking run as now), edits
  in Your version are copied into its `preview_edit`, rating clicks call
  `_on_rating_clicked`, and Accept calls `_use_selected` then
  `get_selected_text()`. Every line of Rephrase's logic, and every name
  its tests patch (`_init_agent`, `_moment_llm`, `scene_desc_edit`,
  `chat`, …), stays where it is.
- **Fallback if that threatens Rephrase:** the Rephrase tab shows the
  hosted dialog whole, with its own lower half, inside the tab. Still one
  window; nothing of Rephrase changes. If even that fails, Rephrase stays
  its own window (the brief's stop rule).

**The old classes during the trial and after.**

- **Trial (D.2b, D.2c):** `PassageCritiqueDialog`, `ExpandStatementDialog`
  and `RephraseDialog` look and behave exactly as they do today (the only
  change is the helper move above, and `hosted=False` by default).
  `improve.open` chooses:
  the switch on → `ImproveWindow`; off → the old class, called as today.
  So every existing test of the old classes passes unchanged, and the
  old windows are one tick away.
- **The switch:** Settings ▸ Features ▸ **Improve window**: "Open
  Rephrase, Suggestions and Overly descriptive? in one Improve window".
  Kept in QSettings as `improve/merged`; a missing key means the default
  (open question 4). An older app ignores it.
- **Retire (its own small step, after you agree):** the switch goes;
  `PassageCritiqueDialog` and `ExpandStatementDialog` become thin
  subclasses of `ImproveWindow` that open on their tab and keep their
  old names (`suggestion_list`, `preview_edit`, `chat`, `discussion`,
  `over_panel`/`panel`, `focus_edit`, `use_btn`, `replacement`,
  `top_tabs`, …) so code and tests that build them keep working;
  `RephraseDialog` stays the hosted class. Tests that look at
  `top_tabs.tabText(1)` get a small adapter that answers with the old
  label.

### 14. Open questions for the writer

1. **The Critique tab.** The brief has four tabs, with Critique last. It
   is the same model call as Suggestions, so it could sit second:
   **Suggestions · Critique · Rephrase · Expand**. Last or second?
2. **The right-click ✨ Improve this ▸ submenu.** Decision 10 keeps its
   three entries as shortcuts, so the count stays 9 / 13. Now that the
   three open one window, should the harness count them as one group
   (9 / 13 becomes 7 / 11, nothing on screen changes)? Recommended: yes.
3. **The Expand tab's name.** "Expand" (the brief) or "Overly
   descriptive?" (the name in the menus and the Companion)? Recommended:
   "Expand", with "Overly descriptive?" as its tooltip.
4. **The switch's starting position.** On for both projects from the
   start (as the five tabs were in D.4), or off until you tick it?
   Recommended: on, since the old windows are one tick away.
5. **Rating an Expand version when Suggestions has not run.** Today it
   cannot be rated. Allow it (saved like any rating, marked "expansion"),
   or leave it unrated as today? Recommended: allow.
6. **Rephrase's "Discard your edit?" question.** With edits kept per
   version, switching never loses an edit, so the question is not needed.
   Drop it, or keep it?
7. **The draft window.** Its right-click Rephrase can open the whole
   Improve window (Suggestions and Expand would then work on drafts too),
   or only the Rephrase tab. Recommended: the whole window.
