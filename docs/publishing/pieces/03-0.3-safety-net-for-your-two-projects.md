## The piece

- **Why:** two projects are in daily use. Tests use made-up projects, which
  cannot prove that yours still open and behave the same.
- **Build:** a script you run with the path to a project. It works on a
  temporary copy and never writes to the original. It:
  - opens the copy, saves it, opens it again, and reports any difference in
    the project, chapters, revisions, style sheet, story memory and notes;
  - confirms the files beside the project (Companion state, critique history)
    still load;
  - opens the main screens on the copy and reports any error;
  - prints a short pass or fail summary.
- **Privacy:** nothing from your projects is copied into the repository or the
  tests, and nothing is sent to a model.
- **How it is used:** run on both projects before the plan starts, to record a
  clean baseline, and again after any piece that touches stored data or the
  project model (1.1, 1.2, 3.1, 3.3, R.3 and the D pieces). Take a checkpoint
  with the app's existing checkpoint feature before trying such a piece on the
  real project.
- **Done when:** both projects pass, and the baseline result is noted here.

## Outcome

**Built (22 November 2026):** `scripts/check_project_safety.py`, with tests in
`tests/test_project_safety_check.py`.

Run it with the path to a project file:

    venv/bin/python scripts/check_project_safety.py "/path/to/Book.writerproj"

It copies the project's text and data files (not audio, video or images) to a
temporary folder, opens the copy, saves it with no changes, opens it again,
and compares. It reports a problem if any file is deleted, any chapter or
revision file changes or shrinks, any field disappears from the project file,
any chapter, novella or section differs after reopening, or the Companion
state or critique history fails to load. It hashes the original before and
after to prove it was not touched. It prints names, counts and checksums only.
