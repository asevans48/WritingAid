## The piece

- **Decided:** LanguageTool is used whenever it is available, and its larger
  language data is offered with the other downloads in configuration.
- **The writer gets:** in the downloads area of Settings, an entry for
  LanguageTool's extra data, with its size, a download button and a remove
  button. With it installed, the grammar check catches more confused words
  ("their" for "there"). Without it, everything works as today.
- **Read first:** `LanguageToolEngine` in `src/utils/proofing.py`, the downloads
  section of `src/ui/settings_dialog.py`.
- **Check first:** the exact data set LanguageTool needs, its size and its
  licence, from LanguageTool's own documentation.
- **Tests:** with the data absent, behaviour is unchanged; the benchmark shows
  more seeded confused words found with it present.
- **Done when:** the download can be added and removed from Settings and the
  Q.2 table shows its effect.

## What has changed since this brief was written

_Added 24 November 2026, after phase 3, D.3 and 2.5 were built. Read the Outcome of each piece named here._

- **Confused words are not "sure" rules.** They stay out of `SURE_RULES` in
  `src/ai/readiness_judge.py`, so the model may still clear them.
- **"Fix all N like this"** is now offered for any flag, including confused
  words, when the writer ticks its box (3.4, changed after review). With the
  larger data there will be more of these. Check the box's wording is clear
  enough that a writer does not change every "there" at once by accident;
  if not, leave confused words out of `fix_all.can_fix_everywhere`.
- **Measure with** `scripts/measure_misses.py` as well as the Q.2 table: it
  counts seeded confused words caught and flags on clean passages.

## Outcome

**Status:** built, 25 November 2026. The data was downloaded once into the
writer's real cache and LanguageTool was checked with it. Nothing committed.

**The data (checked against LanguageTool's own pages):**
`ngrams-en-20150817.zip` from https://languagetool.org/download/ngram-data/
(the only English file there), **8,961,853,713 bytes (9.0 GB)** zipped and
**15,401,820,145 bytes (15.4 GB)** unpacked into `en/1grams`, `en/2grams`,
`en/3grams` (Lucene indexes). LanguageTool's page
(dev.languagetool.org/finding-errors-using-n-gram-data) says "about 8GB",
asks for a fast SSD, and says to point `languageModel` at the folder that
*holds* `en`. It names no licence; the counts are Google Books Ngram data,
which Google publishes under **Creative Commons Attribution 3.0 Unported**
(storage.googleapis.com/books/ngrams/books/datasetsv3.html). Nothing in the
size or licence made it unsuitable.

**Where it lives:** `~/.cache/language_tool_python/ngrams/en` (or under
`LTP_PATH` when that is set), beside the LanguageTool program. On this Mac:
installed, 15.4 GB; 365 GB was free before. The download took 2½ minutes.

**Built:**

- `src/utils/lt_ngrams.py` (new, no Qt): `ngram_root()`, `is_installed()`,
  `language_model_dir()`, `start_download()` / `cancel()` / `state()`
  (a plain background thread with a `DownloadState` the UI polls, so
  closing Settings mid-download is safe), `download_and_unpack()` (resumes a
  partial file with a Range request, refuses unsafe paths in the zip, moves
  the `en` folder into place only when complete, then deletes the zip),
  `remove()`, and `start_language_tool()`: starts LanguageTool with
  `languageModel` when the data is there and **falls back to starting
  without it** if that fails. language_tool_python 3.4 wrongly insists that
  `languageModel` is a file; `start_language_tool` accepts the folder for
  the moment the config is written (`_directory_language_model`).
  Download refuses to start with less than ~25 GB free and says why.
- `src/utils/proofing.py`: `LanguageToolEngine` starts through
  `start_language_tool`; new `ngrams` flag, `request_restart()` (called after
  a download or removal, so the next check restarts LanguageTool with or
  without the data); `describe()` says "LanguageTool, with n-gram data".
  The JVM heap cap (512 MB) is unchanged and enough.
- `src/ui/ngram_download.py` (new): `NgramDataGroup`, a "LanguageTool Extra
  Data" box on **Settings ▸ Language**, under the NLTK downloads and in their
  style: name and sizes, what it is for, source/licence/folder, a progress
  bar, and **one button** that reads Download / Stop / Remove by state, with
  a confirmation before download and removal.
- `src/ui/settings_dialog.py`: three call lines in
  `_create_language_resources_tab` (the file is over 3,000 lines).
- `scripts/score_checks.py`, `scripts/measure_misses.py`: new `--no-ngrams`
  (compare without the data even when installed); the result records and
  prints whether the data was used. `measure_misses.py --languagetool` now
  uses the installed LanguageTool (and data) instead of re-downloading the
  program into its throwaway HOME each run, and closes LanguageTool before
  exiting (it used to leave a Java server running after every run).
- `tests/conftest.py`: every test sees no n-gram data (a temporary folder),
  so results match the rules alone and the real 15 GB is never used.
- `tests/test_lt_ngrams.py` (new, 23 tests; full suite 1,654 passed): presence, start with/without
  data, fallback, restart after download/remove, download (unpack, resume,
  stop, unsafe zip, missing `en`, no space, background thread), the
  Settings entry's three states, and confused-word flags from the data
  staying out of "Fix all".

**Clutter:** Settings is not in the screen harness, so its counts are not in
`screens_baseline.json`. The page gains one box with one button (whose label
changes with the state); nothing else was added. It is the download/remove
the brief asks for, beside the existing downloads.

The Q.2 table does not move: its three missed confused words are "to →
too" (twice) and "it is → its", which are not among LanguageTool's n-gram
pairs. The miss measure, with more and harder confusions, shows the gain,
and no new false alarms on clean prose. Still missed with the data:
his/he's, of/off, to/too, where/were. Run again with
`venv/bin/python scripts/score_checks.py --languagetool [--no-ngrams]` and
`venv/bin/python scripts/measure_misses.py --languagetool [--no-ngrams]`.
`docs/publishing/check_scores.md` and `miss_rates.md` were not rewritten
(printed with `--no-write`).

**"Fix all":** the data's flags have rule ids `CONFUSION_RULE_*`, which
`fix_all.is_confusable` already treats as confused words, so they are never
offered for "Fix all" (decision 9); tested. Unchanged.
