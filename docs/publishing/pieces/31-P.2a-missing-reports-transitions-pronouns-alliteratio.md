## The piece

- **This session: the four reports that are plain scans:** transitions,
  pronouns, alliteration and acronyms. The rest are in P.2b.
- **Goal:** every ProWritingAid writing report has an equivalent here, except
  plagiarism.
- **Add:**
  - **Transitions:** share of sentences that use a transition, and passages with
    none.
  - **Pronouns:** overused pronouns and runs of sentences starting with one.
  - **Alliteration:** runs of words with the same opening sound.
  - **Homonyms:** words easily confused with one that sounds alike, for the
    writer to confirm.
  - **Acronyms:** acronyms used inconsistently or never spelled out.
  - **Sensory detail:** which senses a passage uses and the balance between
    them. It pairs with the overly descriptive check, since both are about
    showing versus telling.
- **Extend:**
  - **Sentence structure:** variety of structures, beyond repeated starts.
  - **Diction:** vague and abstract words, beyond wordy phrases.
- **Confirmed in 0.1:** repeated phrases exist (`OveruseDetector.analyze_phrases`,
  shown in the editor as "Repeated phrase"). A combined view exists only
  partly: the editor's highlights show spelling, grammar, overuse and style
  together, but no single report lists them all. The Style panel lists the
  eleven style checks only. Transitions and sensory detail are named in the
  Critique's model prompts, but nothing counts them.
- **Build:** each as a new kind in `src/utils/style_checks.py`, so it appears in
  the highlighter, the issues list and the readiness report without further
  work. New kinds are off in existing projects until the writer turns them on
  (rule 11).
- **Declutter:** no new screen. The kinds appear in the existing list of checks.
- **Tests:** each new check is added to the benchmark and must meet the Q.2
  target before it is on by default for new projects.
- **Done when:** the report-by-report table in [background.md](../background.md) shows no
  "missing" or "partly".

**Stop and report, as the brief asks:** Few transitions and Alliteration
cannot reach 4 in 5 as scans. What they get wrong is intent, not detection:
every flag is a real run with no linking word or a real run of one sound,
but a writer often means it (a still-life inventory of a dead woman's
kitchen; "the sea lay silver, slow and sliding"). They stay off, and are
for a writer who wants to look. With a model set up, the editor's flag
judge (`flag_judge`) reviews style flags of any kind, which is where intent
could be decided (rule 4). The marked set is small (eight marks), so each
figure moves a lot on one flag.

**None of the four is on by default**, for new projects either: switches
for style checks are not stored anywhere (every editor starts from
`DEFAULT_KINDS`), so "on for new projects only" would need a new
per-project setting. Asked in the checklist, section 3.
