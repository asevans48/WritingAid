## The piece

The writer (27 Nov): "The Write ribbon titles are a bit smashed. Like Word,
icons would be nice as well, with legible titles and accessibility-friendly
pop-up text. We can rename the chapter draft to Chapter and the manuscript
draft to Manuscript." And for 7.4: the recommendations.

1. **Legible tab names.** Home · Review · Insert · Draft read clearly, like
   Word's: a comfortable size (at least the app's body text), padding
   between and around them, the chosen tab clearly marked (an underline
   or a raised tab, with enough contrast in light and dark), and a hover
   state. Nothing squashed at 1024 × 600 or at 150 %. Keep the ribbon
   compact (the writer chose one row in D.13): the tab strip may grow a
   few pixels, but keep most of the 95 px D.13 gained (measure and say).
2. **Icons with labels.** Each control on the ribbon has an icon **and**
   its words (the writer's rule: no icon-only buttons; on narrow screens
   the words shorten, then wrap, never vanish). Use one consistent icon
   style across the four tabs (a small, clear set: the app's emoji style if
   that reads well at this size, or Qt / SVG icons if they are more
   legible; pick one and say why). The font and size boxes and B I U need
   no icon. Optional, only if it fits without losing more than about 16 px
   of text: Word-style small group captions under the controls (for
   example "Font", "Checks", "Notes", "Drafts").
3. **Accessible hover text and names.** Every ribbon control has:
   - a tooltip that leads with its full name, then its shortcut if it has
     one, then one short sentence on what it does (for example
     "Analyze (Ctrl+…): run a report on this chapter or the book");
   - an accessible name and description (`setAccessibleName`,
     `setAccessibleDescription`) so a screen reader says the same;
   - keyboard reach: the tabs and every control are reachable with Tab /
     arrow keys and show a visible focus ring. A test checks every ribbon
     control has a tooltip and an accessible name.
4. **Renames** (same menus, same entries, same shortcuts):
   - this chapter's "📄 Draft ▾" → **"📄 Chapter ▾"** (the "This chapter:"
     label can go if the name now says it);
   - the manuscript's "Drafts ▾" → **"Manuscript ▾"** (with a fitting icon).
   Anything else that names them (tooltips, the Write menu, help text,
   section 1 try-items) follows.
5. **7.4's answers** (the writer took the recommendations):
   - (a) "Scene break here" stays in More ▸ 📝 Note or scene break ▸ on the
     right-click (nothing to build).
   - (b) **Publisher Ready always marks scene breaks** (a centred "#" at
     each marker, as Export Chapter does when ticked). Chapters without
     markers export exactly as before.
   - (c) **The export tick is remembered per project** (stored with the
     project's state, as 7.4 stores markers; a project with no stored
     choice starts unticked, as now).
   - (d) Older tension ratings stay hidden on a marked chapter until the
     next model check (nothing to build).

- **Rules:** 11 (nothing cut, old settings open), 12 (fits at 1024 × 600
  and 150 %), 13 (no count rises: icons and captions are not buttons; say
  if the harness disagrees), 14 (call lines only in files over 3,000
  lines).
- **Done when:** the tab names are legible; every ribbon control has an
  icon and words, a tooltip and an accessible name; both renames are in;
  Publisher Ready marks scene breaks; the export tick is remembered per
  project; the harness passes; the full suite passes.

## Outcome


**Built 27 November 2026 (round 16b), for review. Nothing committed.**
*Review notes* was empty. No model was run; the app was not started.

**What the writer gets.**

- **Tab names you can read.** Home · Review · Insert · Draft at the app's
  body size (13 px, was 12), 14 px of room each side and 4 px between; the
  chosen tab is bold with a 3 px indigo underline (`primary_dark`, about
  6 : 1 on the ribbon's grey); a hover tints the tab and draws a grey
  underline; with the keyboard focus on the tab names a ring is drawn
  round the chosen one, and the arrow keys switch tabs. Each tab name has
  its own hover text ("Review: writing checks, Read Aloud and Analyze.").
  On a narrow Write (640 px window, the side panel open) the tab names
  wrap under "◂ Chapters" instead of scrolling behind arrows.
- **An icon and words on every control.** ✨ became **✨ Improve**; Scene
  break here became **🎬 Scene break here** (🎬 Remove scene break on a
  marked paragraph); the ◂ that hides the chapter list reads **◂
  Chapters**. The rest already had both (✓ Checks, 🗣 Read Aloud, 🔍
  Analyze, 📝 Annotation, 📋 View annotations, ⇅ Split View). The font,
  size and heading boxes and B I U have no icon; B, I and U are now drawn
  bold, italic and underlined, as in Word. Every ribbon button has the
  same plain look (Read Aloud and the manuscript menu used to differ); the
  click-and-arrow buttons (Read Aloud, Annotation) show the arrow inside
  the button's border.
- **The icon set: the app's emoji style.** Chosen because every other
  button in the app already uses it (the writer reads ✓ 🗣 🔍 📝 📋 in the
  same row), it is in colour and legible at 12 px on a Mac, it scales with
  the text at 150 % (Qt's standard icons are small grey glyphs that read
  worse at this size, and SVGs would be a new set of files to keep in one
  style). One wrinkle: 🗣 draws 5 px taller than the other emoji, so Read
  Aloud is a little taller than its neighbours, as it was in D.13; its
  words live in `manuscript_editor.py` (rule 14), so it is left.
- **The renames** (same menus, same entries, same order, same shortcuts):
  this chapter's "📄 Draft ▾" → **📄 Chapter ▾**, and the "This chapter:"
  label is gone; the manuscript's "Drafts ▾" → **📚 Manuscript ▾**
  (also in the top row shown while no chapter is open). The harness groups
  "📚 Manuscript" as it grouped "Drafts" (one line in `GROUPED_MENUS`).
- **Group captions** under the controls (optional) were not added: they
  would cost about 14 px of text at 1024 × 600, nearly three times what
  the legible tab names cost.

**Hover text and screen-reader words.** Each control's tooltip is "Name
(shortcut): what it does." Its accessible name is the name (without the
emoji) and its accessible description the sentence (plus "Shortcut: …"
when it has one); the shortcut is written as the computer writes it (⌘B
on a Mac). The tab names' bar is named "Write ribbon tabs". Tab reaches
the tab names and every control, and each shows a 2 px indigo ring with
the focus. The words:

**7.4's answers.**

- (a) and (d): nothing to build, as agreed.
- **(b) Publisher Ready always marks scene breaks.** Export ▸ Export
  Publisher Ready now puts the centred "#" at each marked scene, in the

  project=None)`, a new optional parameter; the main window passes the

  unreadable file or any other value starts unticked; a project without
  markers never writes it. Another project is not affected. An older app
  keeps the key (unknown top-level keys are kept) and ignores it.
