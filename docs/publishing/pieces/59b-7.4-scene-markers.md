## The piece

- **Why:** the writer's chapters have no scene-break lines, so the scene
  outline (7.1), the model's reading (7.2) and the tension chart (7.3) see
  one scene per chapter, though the model finds 1 to 6. The writer wants
  scenes marked, **but not in the text** (their answer, 27 Nov): the prose
  stays exactly as written.
- **What a marker is:** "a new scene starts at this paragraph", stored
  beside the chapter, never in its text. It is anchored to the paragraph
  by its place *and* its opening words (about 40 characters), so it
  follows the paragraph when text is added or cut above it, and is dropped
  quietly (with a one-line note in the outline) when that paragraph no
  longer exists.
- **Where it is kept:** per chapter, in the readiness state file beside
  the project (`<project>.readiness.json`), which D.10's move already
  carries with a chapter. Only written when the writer adds a marker, so a
  project without markers is unchanged byte for byte.
- **Ways to add and remove one** (no new button on Write):
  - in the Critique's Scene outline ▸: **"Use the model's scenes"**, which
    turns 7.2's reading of the chapter into markers in one step (shown
    first, then confirmed), and a ✕ on each marker line;
  - on Write's right-click: **Scene break here** / **Remove scene break**,
    inside an existing submenu (e.g. More ▸), so the right-click counts do
    not rise (rule 13);
  - Undo for each change (Ctrl+Z in the outline, or the status line's
    Undo, as D.10's moves do).
- **How it shows on Write:** a thin dashed line in the margin above the
  paragraph, with "Scene 2" etc. on hover. Drawn by the editor, not part
  of the text: copying, word counts, grammar checks and saving never see
  it.
- **Who reads it:** `reverse_outline.split_scenes` (and so 7.1's outline,
  7.2's reading, 7.3's chart and plan matching) uses the markers *as well
  as* any break lines already in the text. Nothing else changes.
- **Export:** a standard manuscript marks a scene change with a centred
  "#". **Default: exports leave the text exactly as written** (no break
  inserted); a tick in the export dialog, "Mark scene breaks", puts the
  standard break at each marker in the exported copy only. The writer can
  change this default.
- **Rule 14:** `manuscript_editor.py` and `enhanced_text_editor.py` get call
  lines only; the logic goes in a new module (e.g. `src/data/scene_marks.py`
  for storage and anchoring, `src/ui/scene_marks_ui.py` for drawing and
  menus).
- **Done when:** markers can be added from the outline and the right-click,
  survive edits above them, move with a chapter (D.10, including an id
  clash), show in the margin, feed the outline and chart, never touch the
  text or its saved files, and every count is at or under the baseline.

- **The outline, the model's reading under each scene, the tension and

- **File ▸ Export Chapter / Book** shows one more tick, **Mark scene
  breaks**, only when the project has markers. It is unticked by default
  and the export is then byte for byte what it was before. Ticked, the
  exported copy gets the standard centred "#" before each marked scene
  (Word, RTF, ODT centred; TXT on its own line).

**The text is never touched.** Markers live in `<project>.readiness.json`
under a new top-level key `"scene_marks"`:
`{scope: {chapter id: {"v": 1, "marks": [{"p": 4, "w": "first 40 characters"}]}}}`.
Written only when a marker is added (a project without markers is
unchanged byte for byte: tested), through `readiness_state.update` (safe
write, one lock, other keys kept, read-only for a newer file). The last
marker removed takes the key away again. An older file reads as none; an
older app keeps the key (it keeps unknown top-level keys). The line on
Write is a see-through widget over the editor's viewport, not part of the
document: the document's text, `isModified`, undo stack and revision are
unchanged by marking (tested), and copy, word count, grammar and save see
only the text.

**Anchoring** (`scene_marks.resolve`). A paragraph is a non-blank line
(the editor's block). Each marker is re-found by its opening words, the
nearest to its stored place when several open alike; an opening edited a
little (similarity ≥ 0.75) still finds it. So it follows its paragraph
when text is added or cut above. Its stored place and words are brought
up to date 1.5 s after typing stops (`refresh`, not an Undo step). A
marker whose paragraph is gone is **left out, not deleted**: it comes back
if the paragraph does (Undo, a paste), and the outline offers Forget.

**Moves (D.10).** `chapter_move.move_entries` already moves every
`{scope: {chapter id: …}}` part, so markers travel with a moved chapter,
to the new id after an id clash, and Undo puts the readiness file back
byte for byte (tested both ways). Readers look a chapter up by its
manuscript (by the chapter object when they have it), so a clash's other
chapter never shows the moved one's markers.

**Tension** stores the marker offsets it was rated for (`"marks"`, only
when there are any, so older ratings stay valid); a rating made before a
marker was added or moved is not shown and is asked again at the next
check with the model (tested with a fake model).
