## The piece

- **Decided:** the writer moves chapters forward. The app suggests and never
  moves a chapter by itself.
- **The writer gets:** each chapter shows its stage: structure, scene, line,
  copyedit, proof. The writer changes it from the scorecard or the Companion
  header, forward or back, one chapter or several at once. When a stage's
  checks all pass, the app suggests moving on.
- **Telling the assistant:** the writer can also say it in the AI assistant
  ("move chapters 3 to 7 to copyedit", "put the novella back to line"). The
  assistant confirms what it will move, then moves them. Chapters moved this
  way can still be moved by hand afterwards, exactly like any other.
- **Novellas:** stages work the same in a novella as in the main manuscript, and
  a request can name either.
- **Build:** stage stored per chapter, per manuscript, in `readiness_state`;
  shown in the scorecard and the Companion's chapter header; one new action
  for the assistant.
- **Read first:** `src/ai/chat_actions.py`.
- **Document it:** add the new request to `docs/AI_AGENTS_GUIDE.md`.
- **Tiers:** setting stages by hand needs no model. The assistant route uses the
  assistant's own model, as today.
- **Tests:** a stage set by hand and one set through the assistant are stored
  the same way; a chapter in a novella keeps its own stage; a request that
  names chapters that do not exist changes nothing and says so.
- **Done when:** a stage can be set both ways, is remembered, and the suggestion
  appears when earned.

## Outcome

**Status:** built; waiting for the writer's review. Tests: `tests/test_chapter_stages.py`.

**Stored:** `"stage"` (and `"stage_set": {at, by}`) in the chapter's entry in
`readiness.json` (manuscripts → scope → chapters → id), which the report
already read into `ChapterReport.stage`. Storing results never touches it.
**A chapter with no stage stays unset** ("No stage"), and the queue (3.2)
offers it every stage, so nothing changes for a project until the writer
places a chapter.

**New `src/ai/chapter_stages.py`** (no Qt): `stages`, `stage_of`,
`set_stage(project, scope, ids, stage, by)` (one save; "" clears),
`suggestion_for(stage, statuses)` / `suggestion(chapter_report)` (the next
stage when every counted check of this stage is ready), and for the
assistant `parse_request`, `resolve` and `describe`.

**New `src/ui/chapter_stage_ui.py`:** the stage menu, `ChaptersDialog`
(several chapters at once), `header_html` and `on_header_link` for the
Companion, `install_on_scorecard`, `row_name` and `apply_stages` for the
scorecard, and `run_chat` for the assistant.

**On screen:**
- **Scorecard:** each row's name ends with its stage ("3. The Harbor · Line").
  Right-click a chapter's name for the stages and "Several chapters…". The
  chapter's details show "Stage: Line · change" and, when earned, "Every Line
  check passes. Move it to Copyedit".
- **Companion header:** "· Stage: Line ▾" (a link to the same menu), and the
  same suggestion when earned (from the stored results).
- No new buttons, sections or tabs (harness counts unchanged).

**The assistant:** `chat_actions.detect_intent` recognises "move/put/set …
to <stage>" with any model (`{"kind": "stage"}`), and `main_window` has one
call line. The assistant asks before it moves ("Move chapters 3–7 of “Book”
to Copyedit?"); a chapter that doesn't exist changes nothing and the reply
says which chapters there are. "The novella" means the only novella (or it
asks which); a novella can be named. Documented in `docs/AI_AGENTS_GUIDE.md`.

**Left out:** a model action tag for stages (the plain-language request
works with every model, so a tag would add nothing).
