## Phase context

**The idea.** Ratings stay in one shared store, so everything rated in any
project keeps teaching the app. Each rating is tagged with the voice of the
writing it was given to. Ratings fall into a small number of voice groups.
When the app writes a rewrite, it learns first from ratings in the same voice
group as the passage, whichever project they came from. Two books in different
voices stop colouring each other; two in a similar voice help each other; and
one book with several narrators gets a group for each.

**My reading of "broad, manageable".** Broad: shared across projects, with a
few large groups, not many small ones. Manageable: the writer can see the
groups, rename them, move a rating, merge two groups, and remove ratings.
Correct this in the review notes if you meant something else.

## The piece

- **The writer gets:** a view of ratings grouped by voice: each group's name,
  description, how many ratings it holds and from which projects, and the
  ratings inside it. The writer can rename a group, move a rating, merge two
  groups, change or remove a rating, and rebuild the groups.
- **Where:** inside the screen that already shows rating history (confirm in
  0.2 which that is). No new window or tab (rule 13).
- **Fits rule 12:** the list scrolls, and the view works at 1024 × 600.
- **Done when:** a rating can be found, moved and removed, and a moved rating
  stays where the writer put it after a rebuild.

## Build notes

- **Read first:** `src/data/rephrase_database.py` (`log`, `update_rating`,
  and how rated examples are read), `log_rated_rewrite` and
  `examples_prompt` in `src/ai/rewrite_quality.py`, `src/ai/writer_voice.py`.
- **The ratings database is the writer's learning** (about 200,000 rows).
  Tests use a copy made in a temporary folder, never the real file. No
  existing row or column is altered.
- **Where:** the rating row and history are in `src/ui/rephrase_dialog.py`;
  the training tool (`src/ui/training_tool_window.py`) also lists rated
  rows. Confirm in the session which one shows rating history today and put
  the grouped view there, as a way of sorting the existing list, not a new
  list.
- **Every change the writer makes** (rename, move, merge, remove) goes
  through `rephrase_database` and can be taken back until the view closes.
  Removing a rating asks first; it is the only action here that loses
  something.
- **Tests:** a rating moved by hand stays put after a rebuild; a merge keeps
  every rating; removing asks and removes one row only.

## Review notes

_The writer's changes to this brief, made before the session starts._

- **25 November 2026 (README decision 5):** "manageable" confirmed: see,
  rename, move, merge, remove. Show each group's projects, and mark ratings
  from a project that keeps its ratings to itself (V.4's switch); the
  switch itself can be changed here as well as in the project's settings.
  The groups hold **voice sources** (a project, or a project's narrator),
  and that is what the writer moves between groups; a moved source is
  pinned. Single ratings follow their source (removing a rating stays
  possible). The number of groups is V.2's (as many strong, distinct voices
  as there is evidence for, at most 8 made by the app); say so in a line
  under the groups.
- **Also 25 November:**
  - **Starting groups:** "New group…": a name (optional; the model names it
    otherwise) and what defines it: a project, a narrator, or passages
    marked as examples.
  - **Combine:** select two or more groups ▸ Merge. The result keeps a
    writer-given name if one had it, else the model names it. Undo splits
    them back.
  - **Proposals** from V.2 (a split or merge touching the writer's groups)
    show as one line each with Accept / Decline.
  - **Over 8 groups in all:** one line suggests merging the closest pair,
    only if the merged group would stay strong.
  - **Strength shown:** each group shows how alike its sources are in
    words ("very alike", "alike", "loose") from V.2's separation measure.
    Merging groups whose result would be loose asks first ("these voices
    differ; rewrites will learn less precisely from the merged group"),
    then does it if the writer agrees.
  - **Unsorted** is listed below the groups: sources with too few ratings
    yet (with how many more each needs) and any beyond the 8. A source can
    be moved into a group by hand.
  - Keep the screen within the button baseline (rule 13): actions on a
    right-click or in one menu, not a row of buttons per group.
