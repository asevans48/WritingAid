## Phase context

Phase F makes the app work for stories that are not novels, **keeping every
story feature**: plot, characters, world, critique, the Improve window, Read
Aloud, the Studio. Agreed with the writer on 26 November 2026 (README
decision 18):

- **Kinds.** A project has a kind, chosen when it is created and changeable
  later: **Novel** (novels and novellas, as today, and the default for every
  existing project), **Video series**, **Podcast**, **Editorial series**,
  **Journalism**.
- **Same shape for every kind.** A project still holds a main manuscript,
  novellas and chapters. A kind changes the words on screen (set by the
  kind, editable per project), which checks and goals apply, and what
  publishing prepares. A chapter is one video, one episode or one part.
- **Nothing a novelist has changes.** A Novel project looks and behaves
  exactly as it does before this phase (rule 11). Every test of today's
  behaviour keeps passing unchanged.
- **Phase F comes after the final sweep (9.1).** Sending anything to a site
  (YouTube and others) stays a later integration (decision 7); this phase
  prepares the material.

## Already answered by the writer (26 November 2026)

- A video stands for a **chapter** in a novel, novella or story, and for
  an **episode** in a video series or podcast. One video is never split
  over several chapters.

- A kind is chosen per project (not per manuscript).
- The words are set by the kind and editable.
- Formats covered: video story scripts, podcasts, editorial series,
  journalism, and novels and novellas as they are today.
- An uploaded video goes to the Studio for the selected chapter and
  becomes a card that can be refined there (F.10).
- Spoken formats gain: a runtime estimate, hook and retention checks,
  checks written for the ear, speakers and cues.
- Nonfiction gains: a sources list, an unsourced-claim check, real people
  and a timeline, and fiction checks off.
- Publishing prepares: a video package, a podcast package, an article
  export, a series page, and the novel or novella export, including a
  compilation of a project with its novellas and a single novella on its
  own as a novel, story or short story.

## Design

_Written 26 November 2026 (F.0). Waiting for the writer's review; the open
questions are at the end (§9). Names were checked against the code that
day. No code was written._

**In one paragraph.** A project gets a **kind**: Novel, Video series,
Podcast, Editorial series or Journalism. The kind is one optional line at
the top of the project file, which is absent for a Novel, so every Novel
project's file stays exactly as it is. The shape stays the same for every
kind: a main manuscript, novellas and chapters. The kind changes three
things: the words on screen (from one small module, editable per project),
which checks start on, and what Publish and Export offer first. Spoken
kinds get minutes, cues and speakers, checks for the ear, and a hook and
retention report. Nonfiction gets sources, a claims check, People and a
Timeline. Everything the kind adds is stored beside the project, in files
of its own. Nothing is deleted when a kind hides something, and changing
the kind back brings it all back. The kind is chosen in the New Project box
and changed in Revise ▸ Prose Profile. Neither needs a new tab, window or
toolbar button.

### 1. The kinds and their words

**The words** (these are the defaults; §9 question 1 asks the writer to
confirm them). Each word has a singular and a plural form.

| Word | Novel | Video series | Podcast | Editorial series | Journalism |
|---|---|---|---|---|---|
| The project | Project | Project | Project | Project | Project |
| Main manuscript | Main manuscript | Main channel | Main feed | Main column | Main collection |
| Novella / -s | Novella / Novellas | Series / Series | Season / Seasons | Series / Series | Series / Series |
| Chapter / -s | Chapter / Chapters | Video / Videos | Episode / Episodes | Part / Parts | Article / Articles |
| A heading inside one | (not used) | Section | Segment | Section | Section |
| Unit of length | words | minutes (with words) | minutes (with words) | words (with reading time) | words (with reading time) |
| The audience | reader | viewer | listener | reader | reader |
| Characters (true story, §9 q2) | Characters | People | People | People | People |
| Plot events (true story) | Plot events | Timeline | Timeline | Timeline | Timeline |

- **"Project" stays "Project" for every kind.** It appears in File ▸ New
  Project, Open Project and the title bar. A channel or a show is still a
  project in the app's menus. The writer can rename it.
- **The main manuscript's word appears less often than it seems.** The tree
  shows the main manuscript's *title*, which a new project sets to the
  project's name (`_new_project` creates `Manuscript(title=project_name)`).
  The word appears only when the title is empty and in menus such as
  "Turn main manuscript into a novella…" and "Move main chapters into this
  novella".
- **Reading time** for Editorial series and Journalism is shown beside the
  words, at 230 words a minute. F.3 decides whether to show it (its brief
  says "may").

**Where the words are kept.**

- **Defaults:** in one new module, `src/models/project_kind.py` (no Qt).
  It holds the table above as `KINDS`, and the check table from §3 (F.2
  reads it).
- **The writer's renamed words:** in the project file, at the top level,
  under `project_words`. Only words the writer changed are written, and
  they are kept per kind (§4).
- **Nothing else keeps a word.** Rule 11 already asks for this ("keeps
  those words in one place per screen ... so F.1 can replace them"). No
  shared helper exists yet; F.1 builds it.

**How every screen gets them: one call, `say(project, text)`.**

- **The screen passes the text it shows today.** For example:
  `say(project, "Move to another novella")`, or
  `say(project, f"Chapter {n} of {total}")`.
- **For a Novel project with no renamed words, `say` returns the text
  unchanged**, character for character. This is what guarantees rule 11
  for novelists: a Novel screen cannot change, because the text is not
  touched.
- **For other kinds,** it swaps whole words. It keeps each word's case
  (Chapter → Episode, chapter → episode, CHAPTERS → EPISODES) and plural.
  It also fixes "a"/"an" in front of a swapped word, so "a chapter" becomes
  "an article", not "a article". The words it swaps are chapter,
  novella, "main manuscript", manuscript, and "words" only where it follows
  a count.
- **Two smaller calls** cover the cases where a word is built into a
  sentence: `word(project, "chapter", plural=False)` and
  `kind_of(project)`, which returns `"novel"` when nothing is set.
- **Some sentences read badly after a swap.** For example, "Turn main
  channel into a series…" is fine, but "Turn main series into a series"
  would not be. A screen can give its own wording for one kind with
  `say(project, text, podcast="…")`, which is rare and kept beside the
  text it replaces.
- **Stored names are never swapped (rule 15).** That covers chapter folders
  (`chapter_NNN`), `Subproject.kind = "novella"`, readiness keys, Companion
  section names, check names and the ratings database. `say` is for text
  shown on screen and in exports only.
- **When the kind or a word changes,** open screens are relabelled the way
  opening a project relabels them (`_load_project_into_ui`), after the open
  chapter is saved. F.1 measures how long that takes; if it is slow, the
  screens that show words get a small `apply_words()` instead.

**How many fixed words there are today** (string literals, docstrings
excluded, counted 26 November 2026):

Some of these are dictionary keys or attribute names, not text the writer

**Model prompts.** F.1 does not reword any prompt. For a kind other than

### 2. What a chapter is in each kind

| Kind | A chapter is | A novella is | The main manuscript holds | Headings inside a chapter |
|---|---|---|---|---|
| Novel | a chapter (as today) | a novella | the novel | as today: nothing new |
| Video series | **one video's script** | a story told over several videos (a series) | standalone videos and the main run | sections, which become **timestamps** |
| Podcast | **one episode's script** | a season | the main feed | segments, which become **timestamps** in the show notes |
| Editorial series | one part (one column or essay) | a series of parts | the column | subheads, kept by the article export |
| Journalism | one article | a series (for example a multi-part investigation) | standalone articles | subheads, kept by the article export |

- **One video is one chapter, never more** (the writer, 26 November).
  - A video's card in the Studio belongs to exactly one chapter, through
    the card's existing `chapter_id` (`Scene.chapter_id`, which holds a
    single id).
  - "Add a video…" is offered on one chapter at a time, never on several
    selected chapters.
  - A chapter may have more than one video (a trailer and a reading, or
    two takes), but no video is shared between chapters.
- **A single retelling** (one video) is either a project with one chapter
  or one chapter of the main manuscript among others. Nothing special is
  needed for it.
- **A video stands for a chapter in a Novel too** (a novelist's trailer or
  a reading, F.10). The kind does not change what a video is.

**Sections inside one video or episode.**

- A section starts with a Markdown heading line: `## Cold open` or
  `### The call`. The editor already reads and writes these (the Heading
  Style menu, `enhanced_text_editor.py`). Word import makes them
  (`docx_import`), and every export keeps them.
- Scene breaks (`***`, `#` and the rest of `markdown_editor.SCENE_BREAKS`)
  stay scene breaks. They do not start a section.
- **In spoken kinds a heading is not spoken.** Read Aloud, Listen and mark,
  the word count used for minutes, and the checks all skip it. It is still
  shown in the editor.
- **A heading becomes a timestamp** (F.11). Its time is the spoken words
  before it divided by the speaking pace (F.3), rounded to the second.
  The first section is always 0:00, even when it has no heading. Once a
  real video exists (F.10), the writer can correct the times by hand.

**Cues and speakers** (F.4, decided here so F.4, F.5, F.6 and F.11 agree).
Both are plain text in the chapter, so they survive save, export and
import, and an older app shows them as ordinary lines.

| Mark | Written as | Example |
|---|---|---|
| Cue (not spoken) | `[KIND: text]`, on its own line or inside one, where KIND is one of VISUAL, B-ROLL, MUSIC, SOUND, AD BREAK, NOTE (any case) | `[B-ROLL: the pier at night, rain]`, `[AD BREAK]` |
| Speaker | a paragraph that starts with a speaker's name and a colon | `HOST: Welcome back.` or `Walt: I told them twice.` |

- **Telling a cue from prose:** a bracket followed by `(` is a Markdown
  link, not a cue. A bracket whose first word is not one of the KIND words
  is left alone.
- **Telling a speaker from prose:** a name counts as a speaker only if it
  is one of the project's Characters or People (or an alias of one), or
  Host, Co-host, Guest or Narrator. So a line such as "Note: the bridge
  was closed" in an article is not mistaken for a speaker.
- **In a Novel project** none of this is treated specially (F.4 brief). A
  bracket is a bracket.
- **Not spoken, not counted, not checked:** Read Aloud, Listen and mark,
  the audio export (`export_audio_dialog.py`, which already strips scene
  breaks), minutes and the prose checks skip cues and speaker labels.

### 4. Where the kind is stored

**The rule.** A Novel project's file must not change at all. Today
`save_project` writes `self.model_dump(mode='json')`. That writes **every
declared field of every model, defaults included**. So a declared field
such as `project_kind: str = "novel"` on `WriterProject` would add a line to
every Novel project the next time it is saved. The same is true of a new
field on `Chapter`, `Character`, `PlotEvent` or `Scene`: it would be
written once for every chapter, character, event or card in every project.
So:

- **Nothing in phase F adds a declared field to an existing model.**
- **The kind, its words and the true-story tick are undeclared top-level
  keys** of the project file. `WriterProject` already keeps unknown
  top-level keys (`model_config = ConfigDict(extra="allow")`), so they
  load, are kept, and are written back. The kinds module reads and writes
  them; nothing else does. Each is written **only when it differs from
  Novel**:

  | Key | Example | Absent means |
  |---|---|---|
  | `project_kind` | `"podcast"` (one of `video_series`, `podcast`, `editorial_series`, `journalism`) | Novel. Choosing Novel removes the key; `"novel"` is never written. |
  | `project_words` | `{"podcast": {"chapter": {"one": "Show", "many": "Shows"}}}` | The kind's defaults |
  | `true_story` | `true` | Not a true story |

- **Why the project file, not a side file:** these keys say what the
  project *is*. They must travel with the project when it is copied,
  restored from a checkpoint or moved to another computer without its side
  files.
- **Older versions of the app** keep these keys (they keep unknown
  top-level keys) and ignore them. So an older app opens a Podcast as a
  Novel with today's words and checks, and saves it with the keys intact.
  The project format version is not raised.
- **The name `project_kind`, not `kind`:** "kind" already means
  novel-or-novella in two places, `Subproject.kind` (default `"novella"`)
  and `PublishingGoal.kind`. Neither is touched.

**Kind-only data, and where each part goes.** Every side file is named the
R.7 way (`state_files.own_path`), written only through `safe_store`, and
has a `format_version`. An unreadable file is set aside, never saved over.
Unknown keys are kept, and a file from a newer version is read but never
written. The test set-up redirects each one (rule 15). **A side file is
created only when the writer first stores something in it**, so a Novel
project that never uses these features has none of them.

**Why one `kind.json` and not a file per piece:** fewer files beside the
project, and each piece adds one top-level key to it (`"pace"`,
`"targets"`, `"series"`, `"people"`, `"events"`, `"chapter_videos"`).
Sources get their own file because they hold private details (F.7: never
sent to a cloud model unless the writer says so), and keeping them apart
makes that easy to check.

**Chapters that move (D.10).** Per-chapter entries in `kind.json` are keyed
by chapter id alone, like `companion_state`. So they stay with the chapter
when it moves to another manuscript. On an id clash (rare: chapter ids are
uuids), `chapter_move` must copy them to the new id, as it already does for
the Companion's file. The same holds for the Studio cards' `chapter_id`
(see *Changes the other phase F briefs need*).

### 5. Changing kind later

- **Nothing is deleted, ever.** The kind decides what is *shown*, never
  what is *stored* (rule 11, "Updating the app").

  | When the new kind does not show… | What happens to it |
  |---|---|
  | minutes, targets, pace, series status | stays in `kind.json`, unused |
  | cues and speaker labels | stay in the text. In a Novel they are shown, counted and checked as ordinary text; a one-line note in the status bar says so when the kind is changed. |
  | sources and their links | stay in `sources.json` and in the annotations; the Attributions screen still lists the links |
  | People fields, timeline dates | stay in `kind.json`; the Characters screen shows today's fields |
  | the video and podcast packages | stay in `submission.json` |
  | a chapter's video | stays in the Studio, and the tree keeps its mark (F.10 is for every kind) |
  | renamed words | stay in `project_words` under the old kind, and come back with it |

- **Check switches the writer set by hand are never flipped** (F.2's
  test). When the kind changes, a switch that is still at the old kind's
  starting value moves to the new kind's starting value, and a switch that
  differs from it (the writer set it) stays as it is. The app works this
  out from the two tables, so it needs no record of "set by hand". A
  switch the writer happened to set to the starting value moves with the
  kind, which is harmless.
- **Readiness results are judged again.** The kind joins the readiness
  context fingerprint (`_context_fingerprint`, which already holds the
  route and genre). So results from the old kind are not shown as current,
  and Progress over time (2.4) marks the day the kind changed. Earlier
  results and critique history stay.
- **No question is asked.** A status-bar line says "Kind changed to
  Podcast. Nothing is removed." with an **Undo** button (the D.10 pattern).
  Undo sets the kind back.
- **Changing back to Novel** removes `project_kind`. The project then
  looks exactly as it did before the change, except where the writer
  added something visible to a Novel: cues typed into the text, and a
  chapter's video.

  the kind's word ("Episodes"), and the title bar shows the kind after the
  name for any kind but Novel ("Night Shift (Podcast)"). The AI Assistant
  can change the kind when asked ("make this a podcast"), through the same
  call.

### 9. Open questions for the writer

1. **The default words.** Confirm or correct the table in §1. The
   proposals that are not in the brief's starting point are the main
   manuscript's word (**Main channel**, **Main feed**, **Main column**,
   **Main collection**); **Section** or **Segment** for a heading inside a
   chapter; viewer and listener for the audience; and "Project" kept for
   every kind. *Recommendation: as in the table.* They are only defaults:
   every word can be renamed per project.
2. **How a true story is marked.** Either (a) a **"A true story" tick**
   beside the kind, or (b) a sixth kind ("True story"). *Recommendation:
   the tick.* A true story can be a video, a podcast or a book, so a sixth
   kind would need to be every kind over again. The tick switches on
   People, the Timeline, the sources list and the claims check, and keeps
   the story checks (F.2: "it is a story"). Editorial series and
   Journalism are always true, so the tick is not shown for them. **Should
   it also be offered for Novel** (a memoir, or narrative nonfiction)?
   *Recommendation: yes, unticked.* An unticked box changes nothing, and
   it is the same row as the Kind list (question 4).
3. **A chapter's video file: copied into the project, or linked?** The
   Studio's existing rule (`_upload_clip_for_scene`) **copies** every
   uploaded file into `<project>_video_studio/scenes/<card id>/` as
   `upload_NNN_<date>.<ext>`. *Recommendation: copy, matching the Studio.*
   - The project then holds everything it needs, and a checkpoint with
     "Include Video Studio" ticked holds the video.
   - A writing-only checkpoint (unticked) still skips it, so checkpoints
     stay quick.
   - The writer's original file is never moved or changed.
   - For a file over 1 GB, the box says its size and the free disk space
     before copying. Say if large files should be linked instead.
4. **The one visible change in a Novel project.** The Kind row (and the
   true-story tick, if question 2 says yes) appears on the Prose Profile
   and in the New Project box. Nothing else in a Novel project changes.
   *Recommendation: accept this.* A kind has to be chosen somewhere, and
   this is the least visible place that is still easy to find.
5. **How cues and speakers are written** (§2): `[B-ROLL: …]`,
   `[MUSIC: …]`, `[AD BREAK]` and `HOST: …` at the start of a line.
   *Recommendation: as proposed.* It is the usual script convention, and
   it stays readable in Word, in an older app and in a transcript.
6. **Each kind's export takes Publisher Ready's place in the Export menu**
   (§3, exports): Script for video, Transcript for podcast, Article for
   editorial and journalism. *Recommendation: yes,* so no kind's menu
   grows. Publisher Ready comes back if the kind is set to Novel.
7. **The series status words** (F.13): planned, drafted, revised,
   recorded, published. "Drafted" and "revised" overlap the chapter stages
   (3.1). *Recommendation:* show the stage for those two (so there is one
   source of truth), and store only **planned**, **recorded** and
   **published** as status. For Editorial series and Journalism,
   "recorded" reads **filed**.

**Found in the code** (for the writer to know; no answer needed):

- **The project file writes every declared field.** This is why the kind
  must be an undeclared key, and why no phase F piece may add a field to
  an existing model (§4). It is the one assumption that would quietly
  change every Novel project's file if missed.
- **"Kind" already means novel or novella** (`Subproject.kind`,
  `PublishingGoal.kind`). The main manuscript is always "novel" and a
  novella always "novella" in the publishing goal, and the title page's
  "A Novel by …" / "A Novella by …" comes from that.
- **Readiness checks have no per-project on/off switch today.** Only the
  style kinds have switches (✓ Checks ▾; 4.3's `can_switch_off` offers
  them). F.2 has to add one, or "every check can be turned off per
  project" will not be true for dialogue or point of view.
- **The Studio stores absolute paths** to copied media
  (`VideoClip.file_path = str(dest)`). If a project folder is moved, its
  cards' files are not found. F.10's "a missing file is reported on the
  card" covers this; looking for the file inside the project's own
  `_video_studio` folder before reporting it would fix most cases.
- **A moved chapter's Studio cards lose it on an id clash.**
  `chapter_move._retarget_refs` updates only characters' per-chapter
  readings, not `Scene.chapter_id`, `ChapterDeck.chapter_id` or
