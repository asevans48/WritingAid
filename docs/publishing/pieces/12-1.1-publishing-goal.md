## Phase context

No new screen in this phase except one small form. Its output is a report the
scorecard will display.

## The piece

- **Decided:** the goal is a publishable manuscript, and the one fact the writer
  sets is the **route**: agent submission or self-publishing. Length is not a
  target.
- **The writer gets:** one extra field beside the genre in the prose profile:
  the route. It has a default, so it can be ignored. A novella can have its
  own route.
- **What the route changes:** how strict the opening-pages check is (1.8), which
  export is offered first (9.2), and what the submission package contains
  (9.3).
- **Length:** shown as information beside what is typical for the genre and
  route, per manuscript, so a novella is compared with novellas. It is never
  a pass or fail and never counts toward readiness.
- **Storage:** the route is kept per manuscript in the project's readiness file
  (see 1.2a), not inside the prose profile. A field added inside the prose
  profile would be dropped if an older version of the app saved the project
  (rule 11). With no file, the default route applies.
- **Build:** the route setting; a small
  `publishing_goal` helper that returns genre, route and the typical length
  range, with defaults when nothing is set.
- **Check first:** the Publishing tab (`src/ui/agent_manager_widget.py`) already
  deals with agents and with publishing to Kindle and Barnes & Noble. If the
  route fits better there than beside the genre, put it there; either way it
  is asked once.
- **Read first:** `ProseProfile` in `src/models/project.py`,
  `src/ui/prose_profile_widget.py`, `src/data/genres.py`.
- **Tiers:** no model involved.
- **Tests:** defaults with nothing set; values survive save and load; an old
  project with no readiness file still opens and uses the default; a novella's route is kept separately.
- **Done when:** the route can be set, saved and read back.

## Outcome

**Status:** done. The route can be set, saved and read back, per manuscript.

**Where it is asked: the Publishing tab**, as the brief allowed. "How will
you publish?" is a publishing question. It sits at the top of that tab's
existing "Publishing Actions" box, with one row per manuscript (the main
manuscript and each novella): a route drop-down, defaulting to agent
submission, and the length beside what is typical. The Prose Profile is
unchanged. The route is asked once.

**New:**

- **`src/data/publishing_goal.py`:**
  - `route_for(project, scope)` and `set_route(project, scope, route)`;
  - `publishing_goal(project, scope)`, which returns a `PublishingGoal`:
    manuscript name, kind (novel or novella), route, genre (matched from the
    prose profile's free-text genre by `genres.match_genres`), word count,
    the typical range, and `length_note`, one line of information;
  - `typical_length(genre, route, kind)`, `manuscripts(project)`,
    `readiness_path`, `load` and `save`;
  - `ROUTES = {"agent", "self"}`, with `DEFAULT_ROUTE = "agent"`.
- **`src/ui/publishing_route.py`:** `RouteForm`, which refreshes each time
  the tab is shown (new novellas, word counts, genre).
- `AgentManagerWidget.set_project(project)`, and one line in the main window
  that calls it when a project loads.

**Stored data:** a new per-project file, **`readiness.json`**, beside the
project file. For an unsaved project it goes in `~/.creativeos/readiness/`.
It is written safely through `safe_store`, and an unreadable copy is set
aside rather than overwritten. Layout, `format_version` 1:

    {"format_version": 1, "manuscripts": {"main": {"route": "agent"},
                                          "<novella id>": {"route": "self"}}}

Keys it does not know are kept, ready for 1.2a's results. The project file,
the prose profile and the format version are untouched, so older versions
of the app open the project as before. With no file, every manuscript uses
the default. `tests/conftest.py` sends an unsaved project's file to a
temporary folder (rule 15).

**Length is information only:** for example, "1,200 words. Typical for a
thriller novel sent to agents: 80,000–100,000 (a rough guide)." A novella
is compared with novellas (17,500–40,000). It never says pass or fail, and
it does not count toward readiness. The ranges are a rough guide from
commonly cited agent and self-publishing advice, in one table in the
module.

**Also fixed:** the "Publish to Barnes & Noble Press" button showed "Barnes
_Noble", because Qt reads "&" as a shortcut marker.

**Tests:** `tests/test_publishing_goal.py`, 9 tests:

- defaults with nothing set, and reading never creates the file;
- the route survives save and load;
- an old project with no file uses the default;
- a novella keeps its own route and is compared with novellas;
- other keys in the file are kept;
- an unreadable file is set aside;
- unknown routes are refused;
- the length note never gives a verdict;
- the Publishing tab sets each manuscript's route.

The harness: only the Publishing tab's images changed, and its counts are
unchanged (4 buttons, 1 section). Full suite: 1,013 passed, plus the same
4 `test_overuse_context.py` failures.

**For the next pieces:** 1.2a builds on `readiness.json` and its layout.
1.8, 9.2 and 9.3 read the route with `publishing_goal.route_for`.
