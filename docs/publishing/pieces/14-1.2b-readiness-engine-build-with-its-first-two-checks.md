## The piece

- **This session: build to the design agreed in 1.2a.** Read that file's
  *Design* and *Review notes* first. If the design does not work in practice,
  stop and say why; do not redesign silently.
- **Why:** every later piece plugs into this, so its shape matters most.
- **Build:** new `src/ai/readiness.py` with:
  - `CheckResult`: check name, stage, status (ready, needs work, problem),
    count, the items found (each with its position in the chapter and a
    reason), and whether a model judged it.
  - `ChapterReport` and `BookReport`, the second with one readiness figure.
  - A registry, so a check is one function added in one place.
  - `chapter_report(project, chapter)` and `book_report(project)`.
- **Manuscripts:** reports are per manuscript. `book_report` takes the main
  manuscript or a novella, and a project report lists them all. Use the
  project's own way of listing manuscripts and chapters (confirm in 0.1).
- **Storage:** new `src/data/readiness_state.py`, a per-project file like
  `companion_state.py`, keyed by a hash of the chapter text so unchanged
  chapters are not re-checked.
- **First two checks, to prove the shape:** spelling and grammar flags left, and
  overly descriptive density.
- **Read first:** `src/data/companion_state.py`, `src/ai/overdescription.py`,
  `fix_candidates` in `src/ai/companion.py`.
- **Tiers:** this piece is scan-only. Model judging arrives in 1.7.
- **Tests:** a report for a sample chapter; the cache is used when text is
  unchanged and refreshed when it changes; a check that raises is reported as
  "could not check" and does not break the report.
- **Done when:** both functions return correct reports for a test project.
