## The piece

- **This session: build to the design agreed in 1.2a.** Read that file's
  *Design* and *Review notes* first. If the design does not work in practice,
  stop and say why; do not redesign silently.
- **Why:** every later piece plugs into this, so its shape matters most.
- **Build:** new `src/ai/readiness.py` with:
  - `CheckResult`: check name, stage, status (ready, needs work, problem),
    count, the items found (each with its position in the chapter and a
    reason), and whether a model judged it.
  - `ChapterReport` and `BookReport`, the second with one readiness figure.
  - A registry, so a check is one function added in one place.
  - `chapter_report(project, chapter)` and `book_report(project)`.
- **Manuscripts:** reports are per manuscript. `book_report` takes the main
  manuscript or a novella, and a project report lists them all. Use the
  project's own way of listing manuscripts and chapters (confirm in 0.1).
- **Storage:** new `src/data/readiness_state.py`, a per-project file like
  `companion_state.py`, keyed by a hash of the chapter text so unchanged
  chapters are not re-checked.
- **First two checks, to prove the shape:** spelling and grammar flags left, and
  overly descriptive density.
- **Read first:** `src/data/companion_state.py`, `src/ai/overdescription.py`,
  `fix_candidates` in `src/ai/companion.py`.
- **Tiers:** this piece is scan-only. Model judging arrives in 1.7.
- **Tests:** a report for a sample chapter; the cache is used when text is
  unchanged and refreshed when it changes; a check that raises is reported as
  "could not check" and does not break the report.
- **Done when:** both functions return correct reports for a test project.

**How it behaves**

- **Counts what the editor shows:** a test compares the engine's spelling
  and grammar items with a real editor's underlines for the same text.
- **LanguageTool** results are used when LanguageTool is already running
  (the editor starts it); the engine never starts Java on its own. The
  scorecard also borrows the open editor's ignored words and its
  LanguageTool results.
- **Cache key:** text hash, check name and version, a fingerprint of route,
  genre, opening chapter, thresholds version, vocabulary and LanguageTool,
  and the tier. A failed check is never cached. A 3-chapter book: 0.1 s
  first time, 0.003 s from the cache.
- **Figure:** ready 1, needs work ½, problem 0, over counted cells;
  `BookReport.cells` says how many (0 → the screen shows "—").
- **Rule 15:** before the first write of results into a 1.1-era file, it
  is copied aside once (`readiness.before-1.2.json`). A file stamped with a
  newer `format_version` is read and never written (`BookReport.saved` is
  False). An unreadable file is set aside by `safe_store`. The engine
  writes nothing but `readiness.json` (tested by folder hashes).

**Left out, and why**

- **Grammar dismissal keys** use LanguageTool's rule id (now carried on each
  grammar flag), or `builtin` for the editor's own rules.
- **Book-level checks and history** have their places in the classes and the
  file but no code yet: 1.5, 1.6 and 2.4 add them.
- **Focus and the drafting phase** don't apply to the scorecard: it always
  counts spelling and grammar, whatever the editor is showing.

**For the next pieces:** add a check by writing one decorated function in
`readiness_checks/`. Bump its `version` when it changes, which recomputes
only that check.
