## The piece

- **This session: bring Rephrase into the window built in D.2b,** following the
  D.2a checklist for Rephrase. If the merge threatens Rephrase's behaviour or
  its tests, stop and report; Rephrase can stay separate.
- **The writer gets:** one window for help with a passage, replacing three.
  Tabs along the top: **Suggestions**, **Rephrase**, **Expand**, **Critique**.
  The lower half is shared: the options, an editable preview, the changes
  from the original, the rating buttons, and "Talk it through".
- **Build:** a shared window in a new module. Each existing tool supplies its
  options to it. The existing windows' classes remain as thin wrappers, so
  every place that opens them keeps working.
- **Read first:** `src/ui/passage_critique_dialog.py`, `src/ui/rephrase_dialog.py`,
  `ExpandStatementDialog` in `src/ui/overdescription_panel.py`,
  `src/ui/rewrite_chat_panel.py`.
- **Each tool keeps its own model,** as configured today (rule 2).
- **Risk:** Rephrase is the largest of the three and has its own tests. If the
  merge threatens its behaviour, stop at Suggestions plus Expand and report.
- **Done when:** one window opens from every place the three did, existing tests
  pass, and it fits 1024 × 600 with scrolling.

- **Agreed in 0.2:** the merge goes ahead, with no feature cut. Ctrl+R and the
  ✨ toolbar button keep opening Rephrase, now as a tab of the merged window.

- **Data safety:** accepted text goes into the chapter through the same call
  Rephrase uses today. Rephrase history and ratings are written exactly as
  before.

## Outcome

**26 November 2026: built, for review. Nothing committed.**

**What the writer gets.** Highlight some text and press **Ctrl+R** (or ✨ on
the Write toolbar, or right-click ▸ ✨ Improve this ▸ ✨ Rephrase with AI…):
the **Improve** window opens on its third tab, **✨ Rephrase**, over the
window you are in. The tabs are 💡 Suggestions · 📝 Critique · ✨ Rephrase ·
🔍 Expand (Ctrl+1 … Ctrl+4). On the Rephrase tab:

- a line saying Rephrase works on exactly what you highlighted (the other
  tabs work on whole sentences, as before);
- one line summing up the choices ("Concise · Clearer · Elaborate · Formal
  · Tone: Neutral · POV: keep · Cloud"), and who was detected speaking;
- **▸ Change options** (closed by default, remembered): genre, the seven
  writing styles, point of view, character voice, the twelve tones with
  Custom, and Cloud / Local; 25 options in all, every one as before;
- **Scene** with ↻ Refresh (a style flag's hint is on top, as before), and
  **Generate Options**, with the progress bar beside it.

The options come in as versions ("Rephrase · concise", "Rephrase ·
clearer", …) beside any Suggestions or Expand versions. Below is the
shared half: Your version (editable, ✏ edited, ↺ Reset), Why ("Style: … |
Tone: … — …"), the changes from your highlight, the rating row with 🚫
Avoid a phrase…, Talk it through (Rephrase's own conversation; with no
model it regenerates, as before) and Close / ✓ Accept. **No "Discard your
edit?" question**: each version keeps its own edit and its own rating, so
picking another version and coming back loses nothing (decision 16).
Accepting replaces exactly the highlighted text. ▾ context, beside the
passage, shows the text around it on every tab.

**Every Rephrase caller (D.2a §5 rows 1, 2, 5, 6, 12).** Ctrl+R and ✨,
the right-click entry, a style flag's ✨ Rewrite with AI (hover card and
flag menu) and the next-fix card's 💡 More options… on a style flag (both
send `style_rewrite_requested`) open the window on Rephrase, the hint in
Scene. **The draft window's** right-click ✨ Rephrase with AI… opens the
whole window over the draft window, so Suggestions, Critique and Expand
work on drafts too; Accept writes into the draft and marks it unsaved.

**The old window, one tick away.** Settings ▸ Features ▸ Improve window
now reads "Open Rephrase, Suggestions and Overly descriptive? in one
Improve window" (ticked by default). Unticked, Ctrl+R and every other
caller open the old `RephraseDialog` exactly as before.

**How it is built (D.2a §10: hosted, not rewritten).** The tab holds a real
`RephraseDialog`, built with the new optional `hosted=True` the first time
the tab is shown (opening the window on another tab starts no Rephrase
work, no scene summary). The dialog is never shown; its widgets are moved
into the tab, and the window forwards to it: a picked version selects its
row in the hidden `options_list`, typing is copied into its
`preview_edit`, a rating click calls `_on_rating_clicked` (the same 0.9 s
delayed save, marked "edited"), and ✓ Accept calls `_use_selected`. Every
line of Rephrase's logic, its model (`_init_agent`, `_moment_llm`, Cloud /
Local, the Python libraries with AI off) and every name its tests patch
stay in `rephrase_dialog.py`. `hosted=True` only skips the "Discard your
edit?" question; two new signals (`options_ready`, `save_status`) tell
the window when options arrive and what the save status says.

**Data safety (rule 15).** Accept goes through the same checked replace as
D.2b: `improve.apply` calls `_replace_span(text, start, end, replacement,
"Rephrase")` on exactly the highlight. That gives the same text the old
`cursor.insertText(_tidy_replacement(…))` gave (both tidy the paragraphs
the same way; tested), plus the check that the chapter has not changed
meanwhile. The draft window has its own branch (`improve._apply_to_draft`):
the same check, its own insert, `_set_dirty(True)`. Nothing new is stored
in the project.

**Ratings, history and examples: the same rows (tested).** All of them are
written by the hosted dialog's own calls (`_log_to_rephrase_db` →
`rephrase_database.log_rephrase`), so nothing about them moved. Tests run
the same actions in the old window and in the new tab, each through
Ctrl+R on a fresh chapter, and compare every column but the id and time
in a temporary database:
- rate Excellent, edit, the delayed save; then another option, Poor, edit,
  Accept: four identical rows (excellent / accepted, "concise/neutral |
  edited"; poor / rejected; poor / accepted; the unedited option as
  "neutral") and the same chapter text. The old window asked "Discard your
  edit?" once; the new tab asked nothing;
- Accept with no rating (saved as good): identical;
- a rating still waiting when the window is closed: identical (the new tab
  saves it as the window closes instead of 0.9 s later).
V.4: `rewrite_quality.examples_prompt` is called with the same arguments
(`before`, `after`, `character_name`) by the old window and the tab, and
the "learned from … voice group" note shows in the rating buttons'
tooltip.
