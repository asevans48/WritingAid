## The piece

The writer's idea (27 Nov): "We have a draft and word count row. We could
move word count to the bottom where the Flesch-Kincaid rating is and create
ribbons in the word editor to help free up more space, like Word uses …
formatted like Word. This could help clean up the UI."

The writer's answers (27 Nov):
- **Tabs:** Home · Review · Insert · Draft.
- **Height:** compact, one row: a tab strip over one row of controls (not
  Word's large-icon ribbon).
- **The bottom row:** Analyze ▾ and Draft ▾ move into the ribbon; the
  bottom row keeps the counts and the ◧ Panel toggle.

What goes where (today's Write, from the harness at 1440 × 900):

| Today | Goes to |
|---|---|
| Top row: "Total Words: N" | The bottom row, beside "Words: N" (e.g. "Words: 67 · Total: 12,480") |
| Top row: Editing: [manuscript], Drafts ▾, ⇅ Split View | **Draft** tab |
| Toolbar: font, size, B I U, heading style | **Home** tab |
| Toolbar: ✨ (Improve) | **Home** tab (it is what a writer reaches for while writing) |
| Toolbar: ✓ Checks ▾ (spelling, grammar, style checks) | **Review** tab |
| Toolbar: 🗣 Read Aloud ▾ | **Review** tab |
| Toolbar: 📝 ▾ (Add / View annotations) and the scene break (7.4) | **Insert** tab: 📝 Annotation, View annotations, Scene break here |
| Bottom row: 🔍 Analyze ▾ | **Review** tab |
| Bottom row: Draft ▾ (save / import / drafts) | **Draft** tab |
| Bottom row: ◧ Panel | Stays on the bottom row |
| Bottom row: Words, FK grade, reading ease, Grammar status | Stay; Total joins them |

- **The Chapter Title row goes too** (the writer, 27 Nov: "we can remove
  the chapter title row and users can just manipulate that from the
  manuscript tree on the left"). Today the tree renames novellas but not
  chapters, so add it there first: right-click a chapter ▸ Rename…, F2 and
  double-click edit the title in place (Enter keeps it, Esc cancels, an
  empty title is refused). It saves and updates everything the title box
  did today (the chapter's title, the tree, the window title, exports, the
  Critique), with Ctrl+Z / Undo where the box had it. A new chapter still
  gets its default title. Long titles show whole in the tree (wrap or a
  tooltip, the writer's rule). Nothing else that read the title box breaks
  (find every use of it first).
- **The top row goes**, so Write gains its height for text (measure it:
  with the title row gone too, the target is at least 50 px more text at
  1024 × 600).
- **Home is the tab shown first**, and the tab last chosen is remembered.
  Keyboard shortcuts work whichever tab is showing.
- **Look:** like Word's tab names over one row (D.8's one look: plain
  buttons, the one coloured button rule). Narrow screens: the row shortens,
  then wraps (the writer's rule); nothing is cut off at 1024 × 600.
- **Rule 11, nothing cut:** every entry keeps working, with the same
  shortcuts, and the Write menu and right-click entries are unchanged. Old
  saved toolbar or window state opens without error.
- **Rule 13:** the visible button count should go down. The four tab names
  are new (Write's `inner_tabs` baseline is 0): the writer has agreed to the
  ribbon, so raising `inner_tabs` for Write to 4 is agreed, as long as the
  visible buttons go down; write both figures before and after, and update
  `screens_baseline.json` with an `_about` note. The harness should count
  what is on the shown tab and also report the other tabs' contents.
- **Rule 14:** `manuscript_editor.py` and `main_window.py` are over 3,000
  lines: new logic goes in a small module (for example
  `src/ui/write_ribbon.py`) that moves the existing widgets into the tabs;
  only call lines in the big files.
- **Done when:** the four tabs hold every control listed; the top row and
  the Chapter Title row are gone, chapters rename from the tree, and Total is on the bottom row; Write fits at 1024 × 600 and 150 %
  with more room for text; the harness passes with the agreed counts; the
  full suite passes.

**When no chapter is open** (an empty manuscript, or a moment during a
switch) the old top row comes back with ◂, Total and the draft controls, so
"Editing:" is never out of reach.

**Nothing removed (rule 11).** The same widgets and actions are moved, not
rebuilt: every menu has every entry it had, and everything wired to them
works as before. The old toolbar is kept, hidden, holding B, I, U and ✨
(Home's buttons show those same actions); every action with a shortcut is
also on the chapter editor, so **Ctrl+B, Ctrl+I, Ctrl+U, Ctrl+R,
Ctrl+Shift+N and Ctrl+Shift+H work whichever tab is showing** (tested by
pressing Ctrl+B with Draft shown). The Write menu and the text's
right-click are unchanged (right-click counts still 7 / 11). The title box
is kept, hidden, and still saved, so nothing that read it breaks (every
other reader uses `chapter.title`; the only other use, the dialog behind
the old chapter list's Rename, still updates it). The tab is remembered
under `write/ribbon_tab` in the window-state settings; anything unreadable
there means Home, and no stored setting was renamed or removed.

**Renaming a chapter** (`manuscript_tree.py`): **double-click** a chapter,
press **F2** (handled by the tree, since on a Mac Qt's own edit key is
Enter, which opens the chapter here), or **right-click ▸ Rename…** (was
"Rename", which asked in a box), and the title alone ("The Storm", not "1.
The Storm") is edited in the tree. **Enter** keeps it, **Esc** cancels, and
an **empty title is refused** ("A chapter needs a title, so “…” was kept.").
Spaces are tidied. It saves as the title box did (`set_chapter_title`): the
chapter, the tree and the hidden list, the open editor's title (so saving
keeps it), the window's "unsaved" mark and autosave, and so exports, the
Critique and every other reader of the title. The status bar says
"Renamed “The Storm” to “The Long Storm”" with **Undo**, and **Ctrl+Z** in
the tree does the same. A chapter in a novella that isn't open renames
without opening it. A new chapter still gets its default title ("Chapter
N"). Each chapter row's tooltip shows its whole title (titles elide in the
tree, the writer's rule). A tree rebuild while a title is being typed waits
until editing ends.
