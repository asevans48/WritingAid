## Phase context

Each of these changes no behaviour. They are placed where they make the next
feature pieces smaller and safer. All keep old import paths working and pass
the existing tests unchanged.

## The piece

- **Why:** adding the model server meant editing the same provider map in 26
  places. The next provider would mean 26 more edits and a bug if one is
  missed.
- **Do:** one function that turns a provider name into its `LLMProvider`, used
  by all 26 places.
- **Read first:** `LLMProvider` in `src/ai/llm_client.py`, then search for
  `LLMProvider.SERVER` to find the maps.
- **Done when:** the maps are gone and `tests/test_model_server.py` passes.

- **Data safety:** settings store provider names as words ("claude", "chatgpt",
  "openai", "gemini", "server", and the local kinds). Before changing
  anything, write a test that records what every one of the existing maps
  returns for every name it accepts, including aliases and unknown names.
  The single function must return exactly the same for all of them. No
  setting is renamed, and nothing writes to a settings file in this piece.

## Outcome

**Status:** done, except two maps that were already broken (below).

**Built.** New module `src/ai/provider_names.py`:

- `PROVIDERS_BY_NAME`: the one list. It maps `claude`, `chatgpt`, `openai`
  (an alias for ChatGPT), `gemini` and `server` to their `LLMProvider`.
- `provider_for_name(name, default=LLMProvider.CLAUDE)`: an exact lookup.
  An unknown name gives `default`. `task_llm` passes `None` because it treats
  an unknown name as "no provider", as it did before.

The lookup does no lowercasing or stripping itself. Callers that lowercased or
stripped before still do, at the same place, so the result is the same for
every input.

**Changed.** 24 copied maps were replaced with a call to `provider_for_name`,
plus a local import placed where each map was (same scope, same `try`):
`ai/agent_suite.py`, `ai/field_synthesizer.py`, `ai/model_builder_agent.py`,
`ai/task_llm.py`, `data/corpus_adapters.py`, `services/tts_service.py`,
`ui/characters_widget.py` (2), `ui/export_audio_dialog.py`,
`ui/main_window.py` (7), `ui/manuscript_editor.py`, `ui/plot/plot_manager.py`,
`ui/rephrase_dialog.py` (3), `ui/training_tool_window.py` (2) and
`ui/world_word_dialog.py`. That is 148 lines removed and 48 added. Nothing
was added to the large files beyond the call.

**Data safety.** Before anything changed, every one of the 26 maps was read
from the source and evaluated for 18 names: the five stored names, the local
kinds (`huggingface`, `huggingface_local`, `mlx_local`, `local`), other case
forms, names with spaces, `""`, `None` and unknown names. The results are
recorded in `tests/test_provider_names.py`, and the new function is checked
against them under both defaults. The 24 working maps all gave the same
answers, apart from the `CLAUDE` or `None` default. No setting was renamed,
and nothing writes to a settings file.

**Tests.** `tests/test_provider_names.py` has 38 tests:

- the recorded table, under both defaults;
- the stored names are unchanged;
- no copied map is left in `src/` apart from the two below.

`tests/test_model_server.py` passes. Full suite: 914 passed, 4 failed. The
4 failures are in `tests/test_overuse_context.py`, and the same 4 fail on a
clean checkout of `HEAD` without this change, so they were already failing.

**Left out, for the writer to decide.** `ai/image_generation_agent.py:121` and
`ai/video_generation_agent.py:60` still have their own maps. Both use
`LLMProvider.OPENAI`, which does not exist, so building the map raises
`AttributeError` every time that code runs: the image tool's cloud prompt
helper and the video tool's prompt optimiser. They also lack the `openai`
alias, and the video one returns `None` for an unknown name. Pointing them at
`provider_for_name` would make that code work where it fails today, which
changes behaviour, so it does not belong in a refactor (rule 14). It is a
one-line fix each, `provider_for_name(provider_str)` and
`provider_for_name(provider_str, None)`, best done as its own small fix.
`tests/test_provider_names.py::test_no_copied_maps_left` names both files and
must be updated when they are fixed.

`tests/ai_test_harness.py` also has a map, without `server`. It is test code,
and its behaviour differs from the app's maps, so it was left alone.

**For the next piece.** A new provider is now one line in
`PROVIDERS_BY_NAME`. The API-key lookups next to some maps (`training_tool_window`,
`model_builder_agent`, `corpus_adapters` pick `claude_api_key` /
`chatgpt_api_key` / `gemini_api_key` by hand) are a separate copy that this
piece did not touch.
