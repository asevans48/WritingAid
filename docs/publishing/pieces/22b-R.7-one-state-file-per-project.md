## The piece

- **Found in 3.3:** `readiness.json` and `companion_state.json` are stored
  beside the project file, by folder
  (`Path(project_path).parent / "readiness.json"`). Two projects saved in
  the same folder share them: a pattern dismissed as "Not a problem" in one
  is dismissed in the other, and chapter stages and check results can
  collide where chapter ids match.
- **Decide first** (write the answer under *Review notes*):
  1. **Leave it,** and say in the app that a project should have its own
     folder. No code. Safe if your two projects are in separate folders.
  2. **Name the files after the project** (for example
     `<project file name>.readiness.json`), reading the old shared file when
     the new one does not exist yet. Recommended.
- **If 2, the rules:**
  - **Nothing is lost (rule 15).** The old file is never deleted or
    rewritten. The first save for a project copies what it needs from the
    old file into its own.
  - **Older versions of the app** keep reading the old file, so they see the
    state as it was at the changeover, not later changes. Say so in
    *Outcome*.
  - **One function decides the path,** used by `readiness_state` and
    `companion_state`. No third copy.
  - **Check first** whether either of the writer's two projects shares a
    folder with another project file. If neither does, say so; the change
    is then invisible to them.
- **Tests:** two projects in one folder keep separate dismissals and stages;
  a project with only the old file opens with everything it had; the old
  file is byte-for-byte unchanged afterwards. Tests use temporary folders
  only.
- **Done when:** the decision is recorded and, if 2, two projects in one
  folder no longer affect each other.

## Build notes

_Added 24 November 2026 so a fresh session can finish this piece without searching. Names were checked against the code on that date; if one has moved, find it with a search and say so in Outcome._

- **Decided 24 November 2026: a file per project** (option 2 in the brief).
- **Read first:** `readiness_path` in `src/data/readiness_state.py` and
  `state_path` in `src/data/companion_state.py` (both return
  `Path(project_path).parent / "<name>.json"`); `src/utils/proof_store.py`,
  which calls `readiness_path`.
- **Build:** one function in a new small module (for example
  `src/data/state_files.py`): `state_file(project, kind)` returns
  `<project file stem>.<kind>.json` beside the project file, and the old
  shared name as `legacy`. `readiness_path` and `state_path` call it. Their
  `load` reads the new file, or the legacy one when the new one is absent.
  Their `save`/`update` write the new file only.
- **The legacy file is never written again, renamed or deleted.** The first
  save copies what the project needs into its own file.
- **Whose data is it?** With two projects in one folder the legacy file is a
  mix. Each project takes all of it on first read (nothing can be lost);
  from then on they diverge. Say this in *Outcome*.
- **Projects with no path** (`~/.creativeos/readiness/<name>.json`) are
  already separate; leave them.
- **Also check, report, do not change:** chapter files live in the same
  folder (`load_content_from_file(project_dir)`). If two projects in one
  folder can also collide there, write what you found in *Outcome* and stop;
  that is a saving change and needs its own piece.
- **Tests** (temporary folders only): two projects in one folder keep
  separate dismissals and stages; a project with only the legacy file opens
  with everything; the legacy file is byte-for-byte unchanged after a save;
  `proof_store` finds its data before and after.
- **Stop and report if** any caller builds the path itself instead of
  calling the two functions.
