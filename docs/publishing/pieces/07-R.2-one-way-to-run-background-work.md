the existing tests unchanged.

## The piece

- **Why:** eight places in the interface each keep their own set of running threads and their own
  worker classes. Every new feature in this plan runs model work in the
  background and would add another copy.
- **Do:** one small module with a helper to run a function in the background,
  keep the thread alive until it finishes, report progress, deliver the result
  safely, and support stopping. Move the Companion, Suggestions, Rephrase and
  overly descriptive panels onto it. Older screens move when a piece touches
  them.
- **Read first:** `run_background` in `src/ui/companion_panel.py`,
  `SuggestionWorker` in `src/ui/passage_critique_dialog.py`.
- **Tests:** closing a window mid-run does not crash; an exception in the work
  reaches the caller as an error message.
- **Done when:** the four panels use the helper and their tests pass unchanged.

- **Data safety:** this piece changes how work is run, not what it does with
  the result. Each result is still delivered to the same place, on the main
  thread. A result that arrives after the writer has moved to another chapter,
  or after the text changed, is handled exactly as it is today; where today's
  code applies it without checking, add the check from rule 15 and say so in
  *Outcome*. No worker writes a file. Closing a window mid-run saves nothing
  half-finished.

## Outcome

**Status:** done. Nothing visible changed: the harness gives 68 of 68
images identical before and after, with the same counts. One latent crash
was removed (below).

**New module `src/ui/background.py`:**

- `start(worker)` starts any `QThread` and keeps it alive until its thread
  has finished, through one shared registry, `_RUNNING`. It works for
  workers that shadow `QThread.finished` with their own signal, as
  `RephraseWorker` does. A stand-in that is not a thread, or whose `start()`
  did the work itself (test fakes), is not kept.
- `run_background(fn, on_done, *, on_progress=None, owner=None,
  label=...)` runs a plain function. It returns a `Task`, and
  `on_done(result, error)` arrives on the GUI thread, with `error` set to
  `str(e)` as before. If the function takes a `task` argument, it can
  call `task.report(message)` and check `task.stopping`. `task.stop()`
  drops the result. When `owner` is destroyed (its window closed), the
  result is dropped instead of reaching a dead widget.
- `safe(fn)`: no exception escapes a Qt slot.
- `wait_all(timeout_ms)`.
- `Task`; `BackgroundTask` is kept as its old name.

**Moved onto it** (their worker classes are unchanged; only how they start
and are kept alive):

- **Companion** (`companion_panel.py`): its own `BackgroundTask`,
  `run_background` and `_RUNNING` are replaced by the shared ones. The old
  names still import.
- **Suggestions** (`passage_critique_dialog.py`): `SuggestionWorker`
  starts through `background.start`.
- **Rephrase** (`rephrase_dialog.py`): the scene-summary worker and the
  main `RephraseWorker`.
- **Overly descriptive** (`overdescription_panel.py`): `start_worker`.
- **The conversation panel shared by Suggestions and Rephrase**
  (`rewrite_chat_panel.py`): `run_turn`.

Every module's old `_RUNNING` (and Rephrase's `_RUNNING_MOMENTS`) is now the
shared set, so existing code and tests that wait on it still work.

**Fixed along the way: a crash when closing Rephrase mid-generation.**
`RephraseWorker` was held only by the window (`self.worker`), and nothing
kept it alive. Closing the window while it ran, or starting a second
generation over a running one, could let Python destroy a running thread,
which aborts the app. It is now kept alive, and the window's `done()`
disconnects it, so a late result is no longer delivered to a closed
window. This is the same handling the other windows already had.

**Data safety:**

- No result is applied without the writer. Companion results (recap, notes,
  reader's eye, fixes, overly descriptive) are display-only, and each chapter
  has its own editor and Companion, so a late result can only land in the
  panel of the chapter it was made for. Suggestions, Rephrase and Expand
  change text only when the writer accepts, through the existing path.
- So there was no place where a late result was applied unchecked, and no
  rule 15 check had to be added.
- No worker writes a file. Closing a window mid-run saves nothing.

**Tests:**

- `tests/test_background.py`: 8 tests:
  - the result arrives on the GUI thread;
  - an exception reaches the caller as a message;
  - closing the window mid-run neither crashes nor delivers;
  - stopping drops the result, and the work sees it;
  - progress is reported;
  - a worker with a shadowed `finished` survives losing its only reference;
  - a fake that never starts a thread is not kept;
  - the old names still work.
- The four screens' tests pass unchanged: 185 tests in `test_companion`,
  `test_companion_learning`, `test_passage_suggestions`,
  `test_overdescription`, `test_rephrase*` and `test_rewrite*`.
- Full suite: 979 passed, plus the same 4 `test_overuse_context.py`
  failures that were failing before.

**Left out:** the other screens with their own workers (the main window,
the Critique tab, the Video Studio and others) move when a piece touches
them, as the brief says. `checkpoint_progress.run_with_progress` (added to
fix the checkpoint freeze) waits for its worker with a progress window and
is a different pattern; it stays as it is.
