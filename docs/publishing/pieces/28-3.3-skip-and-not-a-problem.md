## The piece

- **The writer gets:** two more buttons on each fix. **Skip** moves on and
  brings the item back later. **Not a problem** removes it and stops the same
  pattern being raised again.
- **Build:** dismissals are saved in the project's readiness file, so they last
  between sessions and belong to that project alone. A rule the writer wants
  kept permanently is added to the project's style sheet, as today. The
  existing in-memory store of flag verdicts is not used for this: it is lost
  when the app closes and is shared by all open projects.
- **Read first:** `style_sheet.rule_for_flag`, `src/data/companion_state.py`.
- **Tests:** a dismissed pattern does not return on the next check, in another
  chapter, or after a restart, and a dismissal in one project has no effect
  in another.
- **Done when:** dismissed patterns stay dismissed across sessions.

## Outcome

**Status:** built; waiting for the writer's review and the rule 15 safety check
(before and after) on both projects. Tests: `tests/test_next_fixes.py` (3.3
section).

**On the Next fix card (3.2):**
- **Skip** moves the finding to the back of the queue. It comes round again,
  marked "skipped before".
- **Not a problem** removes it and every other place with the same pattern
  (the item's key: the word, or the rule and word). The card says "“very”
  won't be raised again in this project. Undo".
- Key ⌘⇧⌫ for Not a problem, with the 3.2 keys. Companion buttons are still
  15, under the baseline of 18.

**Stored** in the project's readiness file, under `"dismissed"`, the store
the report already applies in every chapter (`readiness._finish`). So a
dismissal lasts across checks, chapters and restarts, and belongs to that
project alone. Each one is marked `"as": "not a problem"`.
`editor_pass.intended` leaves these out, so only what the writer said is
*intended* goes in the editor's brief. The in-memory store of flag
verdicts is not used. The style sheet is unchanged: a rule the writer wants
kept for good is still added as today (💬 Ask → mark deliberate).

**Taking it back:** Undo on the card right after (`fix_queue.undismiss`),
or any time in the Critique, where the check's details list it with "take
that back". That list's wording now reads "intended or not a problem".

**New in `src/ai/fix_queue.py`:** `NOT_A_PROBLEM`, `dismiss(project, entry,
chapter_title)`, `undismiss(project, key)`. `entries` now leaves out
dismissed items, for checks still at needs work.

**For the writer to decide:** `readiness.json` and `companion_state.json` sit
beside the project file (`Path(project_path).parent`, since 1.2b). Two
projects saved in the **same folder** would share them, and with them their
dismissals, stages and results. Projects in their own folders, the usual
layout, are separate (tested). Changing the file's name or place would move
stored data, so it is left for a decision rather than done here.
