- **Capability checklist first:** before removing anything, list
  everything each old screen and switch could do and where it is now (most
  is in the D.4, D.5, D.2c and D.10 Outcomes). Anything without a home
  stops the removal of that item; report it.
- **Backwards compatible (rule 11):** a stored switch setting is left in
  place, unread. A settings file or saved window layout from before (ten
  tabs, the old windows' geometry, the tab row) opens without error. Going
  back to an older version of the app finds its settings as it left them.
- **Rule 15:** the whole-manuscript move must never lose a file. It goes
  through `move_chapters` (which already moves folders by rename, keeps a
  taken name as `_2`, rolls back on failure and offers Undo), not its own
  copy and delete.
- **Rule 14:** in files over 3,000 lines (`main_window.py`,
  `manuscript_editor.py`, `settings_dialog.py`…), removing the old code's
  call lines and branches is fine. New logic goes in small modules.
- **Rule 13:** every count goes down or stays; none rises. Write down the
  new figures; lowering `screens_baseline.json` is the writer's to agree.
- **Done when:** the old screens and their three switches are gone; every
  action on the checklist is reachable; old settings files open cleanly;
  the harness passes with no count above the baseline; the full suite
  passes.

**How the move is built** (rule 14: no new logic in the large files).
`manuscript_tree.move_main_into(me, sp_id)` asks the question and calls
`ManuscriptTree.move_main_into(sp_id)`, which hands every main chapter to
the tree's `move_to` (so `chapter_move.move_chapters`: renamed in place,
a taken name kept as `_2`, readiness and companion state carried, rolled
back on failure, the project saved atomically at the end), then sets the
main drafts' `subproject_id` to the novella and saves once more. If that
save fails, the drafts stay with main (in memory and on disk) and a box
says so; the chapters stay moved, nothing lost. Undo
(`undo_last`) puts the drafts' `subproject_id` back before
`chapter_move.undo`, so its saves carry them, and saves once more.
`ManuscriptEditor._move_main_into_existing` (its name kept: the tree's
menu calls it) is now that one call. The old path made a
`<project>.pre-move-<time>` copy; Undo and the atomic save replace it.
