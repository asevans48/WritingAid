### 0. One decision first: the scorecard must count what the editor shows

The scorecard's counts must match what the writer sees underlined in the
chapter. If it says five spelling problems and the chapter shows three, the
writer trusts neither. Today the rules for *which* flags the editor shows
live inside `WritingHighlighter.highlightBlock`: names, ignored words,
"intended" repeats, the drafting phase, quick rules for dialogue, and
overuse reviewed on light repeats. That method is 241 lines, of which only
16 draw. It needs Qt, so the engine can't call it from a worker thread.

**Recommendation: a small refactor piece, R.6 "One function for the editor's
flags", before 1.2b.**

- Move the decision part of `highlightBlock` into a Qt-free function,
  `src/utils/editor_flags.py: flags_for_paragraph(text, block_number,
  state) -> List[Flag]`. `state` holds the checkers, the modes, the ignored
  sets and the full text.
- The highlighter calls it and only draws.
- No behaviour change. It is checked by the U.2 harness (images identical),
  the Q.2 table (unchanged) and the existing tests.
- Size S. It has the same shape as R.3.

The engine then calls `flags_for_paragraph` for every paragraph of any
chapter, with no window and from any thread. The fallback if the writer
declines R.6 is to run the offscreen highlighter (0.1 measured 0.36 s per
chapter). It must run on the GUI thread in small slices, which makes a
40-chapter check stutter. That is not recommended.

### 1. Addressing: manuscripts, chapters, text

- **Manuscript:** `scope` is `None` for the main manuscript or a novella's
  id. It is stored as `scope_key(scope)`, giving `"main"` or the id
  (`publishing_goal.scope_key`, 1.1). Listed with
  `project.iter_manuscripts()`, main first, and named with
  `project.scope_label(scope)`. **Never `project.manuscript`**, which is
  whichever manuscript is open (0.1).
- **Chapter:** `chapter.id` (a stable uuid), in the order of
  `manuscript.chapters`. To find a chapter's manuscript:
  `project.find_chapter_with_scope(chapter_id)`.
- **Text:** `chapter.content`, or *live text* passed in by the caller for
  the open chapter (`MainWindow._chapters_for_links()` already builds
  `[(id, title, text)]` with it). The engine never reads the editor itself.
- **Opening chapter:** the first chapter of each manuscript
  (`manuscript.chapters[0]`); 1.8 holds it to a stricter standard.

### 2. Data classes (`src/ai/readiness.py`)

All are dataclasses with `to_dict()` and `from_dict()`. Unknown keys are
ignored on reading.

```python
STAGES = ("structure", "scene", "line", "copyedit", "proof")   # the stage ribbon, in order

class Status:                       # string constants, stored as words
    READY = "ready"                 # within the threshold
    NEEDS_WORK = "needs_work"       # over the first threshold
    PROBLEM = "problem"             # over the second
    COULD_NOT_CHECK = "could_not_check"   # the check raised; message says why
    NEEDS_MODEL = "needs_model"     # no model in this tier; left out of the figure
    INFO = "info"                   # information only (length); never a verdict

@dataclass
class Item:                         # one thing found
    start: int; end: int            # offsets into the chapter text checked
    text: str                       # the passage, at most 200 characters
    reason: str                     # why, in one line
    kind: str = ""                  # sub-kind ("spelling", "passive", ...)
    key: str = ""                   # stable pattern key, for dismissals (3.3)
    suggestions: List[str] = []     # fixes, when the check has them
    verdict: str = ""               # "" not judged | "problem" | "cleared" (1.7)
    chapter_id: str = ""            # set for book-level items

@dataclass
class CheckResult:
    check: str                      # registry name, e.g. "spelling_grammar"
    stage: str                      # one of STAGES, or "info"
    status: str                     # a Status word
    count: int                      # items that count: not cleared, not dismissed
    items: List[Item]               # stored up to 200; count is exact
    measure: Optional[float] = None # e.g. flags per 1,000 words, or a density
    message: str = ""               # one plain line for tooltips and empty states
    judged: bool = False            # a model judged the items (1.7)
    version: int = 1                # the check's version (cache)
    error: str = ""                 # set when COULD_NOT_CHECK

@dataclass
class ChapterReport:
    scope: Optional[str]; chapter_id: str; number: int; title: str
    words: int; text_hash: str
    results: Dict[str, CheckResult]  # by check name, registry order
    stage: str = ""                  # the writer's stage (3.1); "" = not set
    is_opening: bool = False
    judged: bool = False             # any result judged by a model
    made_at: str = ""                # ISO time

@dataclass
class BookReport:
    scope: Optional[str]; name: str; kind: str     # "novel" | "novella"
    chapters: List[ChapterReport]
    book_results: Dict[str, CheckResult]           # book-level checks (promises, subplots, ...)
    info: Dict[str, Any]                           # {"length": PublishingGoal (1.1)}
    readiness: float                               # 0..1, "ready for readers" (§6)
    counted: List[str]                             # checks in the figure
    left_out: Dict[str, str]                       # check -> why (needs a model, could not check)
    tier: str                                      # "scan" | "model" | "mixed"
    made_at: str = ""
```

Every `Status` and stage is stored as a plain word, so a newer app can add
one without breaking an older reader. An older reader treats an unknown
status as `COULD_NOT_CHECK`.

### 3. How a check registers: one function in one place

Checks live in small modules under `src/ai/readiness_checks/`, one per
stage family (`copyedit.py`, `line.py`, `structure.py`, `scene.py`,
`opening.py`). `readiness.py` imports them, and registering is a decorator:

```python
@check(name="spelling_grammar", stage="copyedit", label="Spelling and grammar left",
       level="chapter",            # "chapter" | "book" | "project"
       needs_model=False,          # True: NEEDS_MODEL in the scan tier
       counts=True,                # False: shown, never in the readiness figure
       threshold=Threshold(per_1000=(0.5, 2.0)),   # ready ≤ 0.5, problem > 2.0
       version=1)
def spelling_grammar(ctx: CheckContext) -> CheckOutput:
    ...
```

- `Threshold` is either `per_1000=(needs_work_above, problem_above)` on the
  rate of counted items, or `count=(a, b)` on the plain count, or `None` when
  the check sets its own status. `ctx.threshold(name)` returns it adjusted
  for the route, the opening chapter (1.8) and, later, the genre baseline
  (P.3). Every adjustment happens in that one function.
- `CheckOutput(items, measure=None, status=None, message="")`. The engine
  works out `count` (dropping cleared and dismissed items) and `status`
  (from the threshold, unless the check set one).
- **Registry order** is column order within a stage on the scorecard.
- `REGISTRY: Dict[str, CheckSpec]`, `checks_for(stage=None, level=None)`.

**`CheckContext`** (one per chapter run, built by the engine):

- `project`, `scope`, `chapter`, `text`, `words`, `is_opening`, `route`
  and `genre` (both from 1.1's `publishing_goal`), `llm` (`None` in the
  scan tier), and `names` (characters, world elements, the project
  dictionary and style-sheet allowed words, as
  `EnhancedTextEditor.set_project_vocabulary` builds them);
- **shared, lazily computed scans**, so checks never repeat expensive
  work: `ctx.editor_flags()` (R.6's `flags_for_paragraph` over every
  paragraph), `ctx.style_issues()` (`style_checks.analyze_document`),
  `ctx.overdescribed()` (`overdescription.scan`), `ctx.speech()`
  (dialogue lines and profiles), `ctx.stats()` (`ProWritingAnalyzer`).

**`BookContext`** for `level="book"`: `project`, `scope`, the chapters with
their texts and reports, and `planning` (`story_planning`). `level="project"`
is for checks across manuscripts, such as continuity across novellas
(1.6). Their items carry `chapter_id`.

**The first two checks (1.2b):**

- `spelling_grammar` (copyedit): `ctx.editor_flags()` of families
  spelling and grammar, one item each, with the flag's suggestions. The
  key is `spelling:<word lower>` or `grammar:<rule id>:<text lower>`.
- `overdescribed` (line): `ctx.overdescribed()` flags as items. The
  measure is flags per 1,000 words; the threshold is `per_1000=(2.0, 5.0)`,
  provisional and tuned against the Q.2 benchmark.

### 4. The engine (`src/ai/readiness.py`)

```python
def chapter_report(project, chapter, *, scope=None, text=None, llm=None,
                   use_cache=True, checks=None) -> ChapterReport
def book_report(project, scope=None, *, texts=None, llm=None, use_cache=True,
                progress=None, stop=None) -> BookReport
def project_report(project, **kw) -> List[BookReport]      # main first, then each novella
def readiness_figure(report: BookReport) -> float
```

- **Never raises.** Each check runs in its own `try`. A failure becomes
  `COULD_NOT_CHECK`, with the message and the error, and the rest of the
  report carries on (1.2b tests this).
- **Scan tier** (`llm=None`): checks with `needs_model=True` get
  `NEEDS_MODEL` and are listed in `left_out`.
- **Model tier** (1.7): after the scan, the candidates for each stage are
  judged in **one model call per stage per chapter**. A check opts in by
  giving a `judge` prompt builder (`compact` for local models,
  `is_local_llm`). Cleared items keep `verdict="cleared"` and stop
  counting. An empty or unreadable reply leaves the scan result.
  `result.judged = True`.
- **Dismissals** (3.3): items whose `key` is in the project's dismissals
  are left out of `count`, but stay in `items`, marked, so a "show
  dismissed" view is possible.
- `progress(done, total, chapter_title)` and `stop()` serve 2.3's
  background run (R.2's `run_background`). `book_report` saves each
  chapter's results as it finishes, so stopping or closing loses nothing.
- **Pure Python, no Qt** (given R.6), so it runs on a worker thread. The
  caller collects live text on the GUI thread before starting.
- **Writes nothing but `readiness.json`.** It never writes the project
  file, a chapter file or a revision. A test checks the project folder's
  files, by hash, before and after a report.

Helpers for the screens:

- `grid(book) -> rows × columns` with status and count per cell, grouped by
  stage (2.1);
- `items_for(report, check)` (2.2);
- `fix_candidates_for(book_or_chapter, stage)` returns items in the same
  shape as `companion.fix_candidates`, so 3.2's queue reuses the Companion
  code unchanged.

### 5. The cache key

A chapter's result for one check is reused when **all** of these are
unchanged:

```
sha256(text with "\r\n" → "\n")          # the chapter text ("text_hash")
check name + check version               # a changed check recomputes only itself
context fingerprint = sha256(route, genre key, is_opening,
                             thresholds version,
                             vocabulary hash (names, dictionary, allowed words, kept kinds),
                             languagetool on/off)
tier                                     # "scan", or the model's id for judged results
```

- Dismissals are applied when the report is assembled, so dismissing never
  invalidates the cache.
- Book-level results are keyed on the ordered chapter hashes plus a hash of
  the story planning (promises, subplots, events).
- On average a chapter's scan costs about 0.4 s, almost all of it the
  editor flags. With the cache, a 40-chapter book costs that only for
  chapters edited since the last check.

### 6. The readiness figure ("ready for readers")

Over the **counted** cells of a book (chapter by check, for checks with
`counts=True` whose status is `READY`, `NEEDS_WORK` or `PROBLEM`), a ready
cell scores 1, needs-work ½ and a problem 0. The figure is the mean, shown
as a percentage. It leaves out `NEEDS_MODEL`, `COULD_NOT_CHECK` and `INFO`
(length), and says so in `left_out`. Book-level checks count as one cell
each. The formula has a version stamp (`FIGURE_VERSION = 1`), stored with
the history (2.4), so a later change of formula doesn't look like
progress. The word "publishable" is never attached to the number (2.1).

### 7. The readiness file (`src/data/readiness_state.py`)

It owns **`readiness.json`**, beside the project file. 1.1 created it, and
`publishing_goal.load` and `save` become thin calls into this module in
1.2b. It is written only through `safe_store`, which writes safely and
sets an unreadable file aside. Writes go through one function guarded by a
lock: load, change one part, save. That keeps a background run (2.3) and
the GUI from overwriting each other's parts.

```json
{
 "format_version": 1,
 "manuscripts": {
  "main": {
   "route": "agent",
   "chapters": {
    "<chapter id>": {
     "stage": "line",
     "text_hash": "sha256:…", "context": "sha256:…",
     "results": {"spelling_grammar": {"…CheckResult…": "", "tier": "scan"}},
     "made_at": "2026-11-23T10:00:00"
    }
   },
   "book": {"key": "sha256:…", "results": {"…": "…"}},
   "history": [{"date": "2026-11-23", "readiness": 0.62, "figure_version": 1,
                "tier": "scan", "counts": {"spelling_grammar": 14}}]
  },
  "<novella id>": {"route": "self", "chapters": {}, "history": []}
 },
 "dismissed": {"spelling:vethari": {"check": "spelling_grammar", "at": "2026-11-23"}},
 "acceptance": {"spelling_grammar": {"accepted": 12, "skipped": 3, "not_a_problem": 1}},
 "voice": {"main": {"voice": "…", "style": "…", "habits": ["…"], "sample": "<hash>",
                    "model": "…", "made_at": "…", "version": 1}}
}
```

- **`voice`** (added after 1.2a, `src/ai/voice_profile.py`): the AI reading
  of each manuscript's style and voice, made by the Critique when a model is
  configured and reused until the sampled prose changes. The engine keeps it
  as it is; checks may read it through the `WriterVoice` in the context.

- **Per project, never shared:** dismissals (3.3), acceptance counts (4.3)
  and stages (3.1) belong to this file alone, so nothing done in one
  project changes another (rule 11).
- `stage` absent means "not set". 3.1 decides what "not set" shows.
- **History** (2.4): one entry per day per manuscript, at most 365,
  oldest dropped. It holds the figure and its version.
- **Size:** at most 200 items per check per chapter. For a 40-chapter book
  that is well under 1 MB.
  *(Built in 1.2b–1.6: 80 items, 25 when ready, 40 when it needs a model; written
  compactly and in batches. With 16 checks, a 102,000-word novel is about 1.8 MB.)*

**When the file is …**

| Missing | Defaults: route `agent`, no stage, nothing cached. Nothing is written until there is something to save. |
|---|---|
| Unreadable | `safe_store` renames it aside and tells the writer once, then starts afresh. Results are recomputed. Route, stages and dismissals are in the set-aside copy; the message says so. |
| From a newer version (`format_version` greater than this app knows) | **Read-only:** whatever this version understands is read, and the engine **never writes the file** in this session, so newer data can't be lost. The scorecard says the results weren't saved. |
| Holding unknown keys | Kept as they are on every save (load, change, save the whole dict). |

### 10. Open questions for the writer

1. **R.6 before 1.2b** (§0): agree to the small refactor, or accept the
   offscreen-highlighter fallback.
2. **The figure's weighting** (§6): "needs work" counts as half. Simple
   and explainable; an alternative is to count only ready cells.
3. **The overdescription threshold** (§3): 2 per 1,000 words is
   "needs work" and 5 a "problem". The clean published prose in the Q.2
   benchmark runs at 8.1 per 1,000 with today's scan, so as it stands this
   check would mark published books as needing work. Either raise the
   thresholds for the scan tier, or count only model-confirmed flags once
   1.7 exists. The suggestion is to count it only when a model judged it,
   so it is `needs_model` in the scan tier, until P.5 improves the scan.
