## The piece

- **Where:** the existing Publishing tab (`src/ui/agent_manager_widget.py`),
  which already holds literary agent contacts and composes emails to them.
  The package is added there. No new screen.
- **Parity with:** ProWritingAid's marketability analysis.
- **Also gives:** who the book is for and where it sits among comparable titles,
  drawn from the genre list and the manuscript.
- **The writer gets:** drafts of a synopsis, a query letter and a blurb, plus
  comp titles from the genre list.
- **Tiers:** without a model, a filled-in template built from the plot and story
  memory. With one, drafts in the writer's voice that the writer edits.
- **Done when:** all three documents can be produced and exported.

**Where the writer finds it.** Publish ▸ Publishing: the first entry in the
"Agents & Publishers" list is now **📦 Submission package**. Choosing it
shows the package where an agent's details are shown. No new tab, screen,
section or dialog. In it:

- a document picker: **Synopsis · Query letter · Blurb · Readers and
  comps** (and a manuscript picker, shown only when the project has
  novellas: each manuscript has its own package);
- one status line: who made the text (filled in from the story, drafted by
  the model, or written by you), when, "edited by you", a rough voice fit
  for a model's query or blurb, how many earlier versions are kept, and
  **where the drafts are kept**;
- the draft itself, editable; every edit is stored as it is typed;
- one button, **✍ Fill in from the story** (no model set up) or **✍ Draft
  in my voice** (a model set up), and one **More ▾**: Fill in from the story
  (no model) · Draft in my voice with the model · Export this document… ·
  Export the whole package… · Earlier versions ▸.
- On "Readers and comps" only: the candidate comparable titles as tick
  boxes, a line for your own titles, and the honest note (below).

**The tiers.**

- **Without a model (the full tier).** Opening an empty document fills it
  in from what is already in the project: the main plot, the plot
  structure's stage texts and events (in act and stage order), subplots,
  themes, tensions' stakes, the protagonist's want, need and the lie they
  believe, the antagonist, chapter summaries (used when the plot structure
  is empty), the prose profile's tone and style, the publishing goal (genre,
  novel or novella, words) and the title-page details from 9.2 (byline,
  email, phone, to sign the query). What is missing is left as a
  [bracketed] prompt, so every document is always complete. The synopsis
  gives the ending; the blurb and query keep it back.
- **With a model.** The model Rephrase uses (`word_suggest.get_llm()`, rule
  2), one call per document, given the filled-in template, chapter
  summaries (synopsis), the story memory (`story_memory.prompt_block`), the
  writer's measured voice (`writer_voice.project_voice(...).to_prompt()`)
  and the chosen comps. Local models get a compact prompt
  (`is_local_llm`). The call runs on a worker thread
  (`background.run_background`); an on-device model is used inside
  `mlx_utils.MLX_GENERATE_LOCK`, waiting for any other feature using it.
  A failed or near-empty reply changes nothing and says so. For "Readers
  and comps" the model writes only "Who it's for"; the comps list and
  "Where it sits" are the app's facts, appended unchanged.

**Comparable titles: honest about what the app knows.** Candidates are the
genre list's `comps` (`src/data/genres.py`) for the book's genre, then its
close neighbours, at most 12. They are published, public-domain classics.
The screen says so, says the app doesn't judge whether a book is
comparable, and says agents usually want recent titles, which the app
cannot know, so there is a line for the writer's own. The model is given
only the titles the writer chose and told to name no others. No sales
figures anywhere.

**Who it's for and where it sits** (ProWritingAid's marketability): a
"Who it's for" paragraph (readers of the genre, the tone and style, the
themes, an [age group] prompt); the chosen comps; and "Where it sits":
the length beside what is typical (`publishing_goal.length_note`), then
sentence length and dialogue share measured over the manuscript (sampled
evenly to 60,000 words) beside published books in the genre
(`genre_baseline.line`, P.3) when the baseline is built, else beside the
Critique's rules of thumb (`resolve_genre_profile`), labelled "not measured
from published books"; and a line that the app knows nothing about sales,
recent titles or what an agent will take. Information only, no verdicts.

**Where the drafts are stored.** Per project, the R.7 way:
`<project>.submission.json` beside the project file
(`state_files.own_path(project, "submission", "submission")`;
`~/.creativeos/submission/` for a project not yet saved). Never in the
manuscript or the project file; an older app does not know the file and
leaves it alone. Written only through `safe_store`; an unreadable file is
set aside, never saved over; keys the app doesn't know are kept; a file
from a newer version is read, never written.

**Nothing the writer wrote is lost.** A new draft (template or model)
first puts the current text into the document's earlier versions (unless
it is empty or the same). More ▾ › Earlier versions lists them (date,
whose, first words); restoring one keeps the current text the same way.
The status line says "Your earlier text is kept: More ▾ › Earlier
versions." A draft that finishes after the writer moved to another
document is stored for the document it was asked for, never the one on
screen; the writer's typing is stored before a draft lands.

**Export** uses the existing exporter
(`ManuscriptExporter.export_document`): Word, RTF, OpenDocument or plain
text. One document has no title page; the whole package has the book's
title and byline, then each document as a headed section.

### Addendum 27 Nov: the query addressed to the chosen agent

**What changed for the writer.**

- **In the package, on the Query letter only:** a **To** list beside the
  document picker: "To: no agent chosen", then each agent in the list
  ("To: Ada Voss · Harbour Literary"). Long names elide; the full name is
  in the item's tooltip. Choosing an agent addresses the letter to them;
  choosing "no agent chosen" puts today's text back. No new button.
- **The letter.** With an agent chosen, the greeting is "Dear <name>,",
  and one line after the book's details uses what the agent list already
  holds: "I'm querying you because you represent <what they represent>,
  and I hope THE PIER might be right for your list at <agency>." (or the
  part of it the list holds; nothing when it holds only a name). What
  they represent comes from a line in the agent's Notes starting
  "Represents:" (also "Looking for:", "Wishlist:", "MSWL:"); the Notes
  placeholder now says so. With no agent chosen the letter is exactly
  today's text, "Dear [Agent's name],".
- **Compose Email to Agent** (an agent's page) now works: it addresses the
  package's query letter to that agent the same way, then opens a draft
  in the writer's own mail program (a `mailto:` link) with the agent's
  stored email in To (left empty when none is stored), "Query: <title>"
  as the subject and the letter as the body. **Nothing is sent**: the
  mail program shows the draft. If the mail program can't be opened, the
  letter is copied and the writer told to paste it; the clipboard is not
  touched otherwise. Without a project open it opens an empty draft to
  the agent. The package, opened afterwards, shows the same letter with
  that agent in To.
- **The writer's text is kept** (rule 15, the package's own way). A
  letter the app filled in and the writer hasn't touched is filled in
  again for the new agent. A letter the writer has edited is never
  refilled: the app asks "You've edited your query letter. Change only
  its greeting to “Dear …,”?"; Yes changes only the greeting (and the
  app's own agent line, if still there word for word), No leaves it
  exactly as it is (Compose Email then uses it as is). A model's draft
  has its greeting changed without asking. Every change first puts the
  current text into Earlier versions, and the status line says so. A
  letter with no "Dear …," line is left as it is, and the status says
  why. A new draft (Fill in from the story, or the model) is addressed
  to the chosen agent; the model's greeting is replaced by the app's.

**Where it's kept.** The chosen agent is stored with the query letter in
the drafts file (`<project>.submission.json`, new key `"to"`: id, name,
agency, email, represents). An older app doesn't know the key and keeps
it; a file from before this addendum has no `"to"` and means no agent.
Nothing new in the project file; `AgentContact` is unchanged.
