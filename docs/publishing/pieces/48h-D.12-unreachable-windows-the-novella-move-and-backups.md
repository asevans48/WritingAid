## The piece

The writer's answers (27 Nov): "delete any old windows that are unreachable.
We can use the undoable move to a novella; we should also alert people to
the irreversible nature of doing this. Please fix the backup copy bug."

1. **Delete every window nobody can reach any more.**
   - Known: the old Suggestions window (`PassageCritiqueDialog`) and the old
     Overly descriptive? window (`ExpandStatementDialog`). The Improve
     window uses helpers in their modules, so keep the helpers (move them
     if that is cleaner) and delete only the dead window classes.
   - Then sweep for others: any `QDialog` / `QMainWindow` / window class
     that no live code path opens (not a menu, button, shortcut, right-click,
     assistant action or another window). List each candidate with the
     evidence, delete the ones that are truly unreachable, and report any
     that are doubtful instead of deleting them.
   - Capability checklist first (as D.11): what each could do and where it
     is now. Anything without a home is kept and reported.
   - Tests that checked features through a deleted window move onto the
     Improve window (or the live place), so coverage doesn't drop.
2. **"Turn main manuscript into a novella…" uses the undoable move.** It
   goes through `chapter_move.move_chapters` like "Move main chapters into
   this novella" (renamed in place, `_2` for a taken name, rollback on
   failure, Undo in the status bar). Nothing else about it changes (same
   entry, same place, same result).
   - **Warn plainly about what cannot be undone.** Its confirmation (and
     "Move main chapters into this novella"'s) says in one or two plain
     sentences what happens and exactly what Undo does and does not cover
     (for example: Undo lasts until the app closes or the next move; any
     part that cannot be put back says so). Find out what is really
     irreversible before writing it; don't overstate or understate.
   - Also list (report only, no change) other actions in the app that
     can't be undone and don't say so, for the writer to decide.
3. **The backup-copy bug (rule 15).** A chapter's saved copies
   (`backup_*.md`) are named to the second, so two saves in one second
   write the same file and the earlier copy is lost. Give each copy a
   unique name (for example, add microseconds or a `_2`, `_3` suffix), so
   no copy is ever overwritten. Old copies keep their names and are still
   listed, sorted and restored as before; any code that parses the name
   reads both forms. Find every place that writes such copies.

- **Rules:** 11 (nothing cut; old files and settings open), 13 (counts go
  down or stay), 14 (call lines only in files over 3,000 lines), 15.
- **Done when:** the dead windows are gone with their tests moved; the
  novella move has Undo and an honest warning; two saves in one second keep
  two copies; the harness passes; the full suite passes.
