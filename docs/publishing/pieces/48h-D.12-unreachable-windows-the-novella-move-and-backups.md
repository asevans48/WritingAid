   no copy is ever overwritten. Old copies keep their names and are still
   listed, sorted and restored as before; any code that parses the name
   reads both forms. Find every place that writes such copies.

### 2. The novella move

"Turn main manuscript into a novella…" (the main row's right-click; the
first novella's "Move into …" button; the offer after dropping the last
novella) now makes the novella and calls `ManuscriptTree.move_main_into`,
the same as "Move main chapters into this novella": every main chapter
through `chapter_move.move_chapters` (folders renamed, a taken name kept
as `_2`, everything put back on failure), the main drafts with them, Undo
on the status bar. Same entry, same place, same result (the novella open
on its first chapter, the main manuscript empty). The "Chapters Moved" box

`move_main_content_to_subproject` (the old copy, check, delete) is no

`undo_note`, `draft_open`, `announce_again`; in `manuscript_editor.py`
only call lines (its 30-line body became one call).

**What is really irreversible (checked first):**
- Undo is the status bar's button: it shows for 30 s (`NOTICE_MS`) and
  goes when another status message replaces it, at the next move, or when
  the app closes. Only the last move.
- After that, chapters can still be moved back by hand (right-click ▸
  Move to, or drag). The drafts cannot: nothing else in the app changes a
  draft's manuscript, so they stay with the novella.
- Undo puts the chapters, files, state files and drafts back; it does
  **not** remove the novella that "Turn main…" made (it stays, empty).
- Nothing is deleted at any point (folders are renamed), so nothing is
  lost even without Undo. The old `.pre-move-` copy of the project file is
  no longer made (Undo and the atomic save stand in for it, as in D.11).

### 3. Backup copies

`Chapter._save_working_backup` is the only writer of `backup_*.md` (the
old `working_backup.md` migration in it was a second, which could also
write over a copy; both now go through `chapter_backups`). A copy keeps
the old name, `backup_YYYYMMDD_HHMMSS.md`, when the second is free; a
later copy in the same second is `…_2.md`, `_3` … (one higher than the
highest of that second, so order holds even after pruning), created
exclusively (`open(…, "xb")`), so no copy is ever written over
(`new_path`, `copy_new`). `parse_name` reads both forms (`_list_backups`):
the Nth copy of a second is dated N − 1 µs later, so copies sort in the
order made, prune as before, and each restores by its own time. Revert to
Saved Copy ▸ shows "(2)" after a same-second copy's time (`label`; one
call line). Other names (`backup_1.md`, `…_1.md`) are not copies, as
before. An older app lists only the first form and leaves `_N` copies
alone. Files: `src/models/chapter_backups.py` (55 → 132 lines),
`src/models/project.py` (2,628 → 2,626).
